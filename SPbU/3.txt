# 1. Языки программирования и основные парадигмы

## 1.1. Понятие языка программирования

**Язык программирования** — формальная знаковая система, предназначенная для описания данных, алгоритмов и вычислительных процессов в форме, допускающей автоматическое исполнение или трансляцию.

Язык характеризуется:

1. **лексикой** — правилами образования идентификаторов, чисел, ключевых слов;
2. **синтаксисом** — правилами построения программ;
3. **статической семантикой** — условиями корректности, проверяемыми без выполнения;
4. **динамической семантикой** — правилами исполнения конструкций;
5. **системой типов**;
6. **моделью памяти и вычислений**;
7. **стандартной библиотекой и средой исполнения**.

По способу исполнения выделяют:

- компилируемые языки;
- интерпретируемые языки;
- языки, транслируемые в промежуточный код;
- языки со смешанным выполнением и JIT-компиляцией.

Эта классификация относится не только к языку, но и к его реализации: один и тот же язык может иметь как компилятор, так и интерпретатор.

По вычислительной парадигме рассматривают:

- императивное и процедурное программирование;
- функциональное программирование;
- логическое программирование;
- объектно-ориентированное программирование.

Современные языки обычно являются **мультипарадигменными**.



## 1.2. Процедурное программирование

Процедурное программирование является развитием императивной модели.

Программа рассматривается как последовательность команд, изменяющих состояние вычислительной системы:

\[
S_0\xrightarrow{c_1}S_1\xrightarrow{c_2}\cdots
\xrightarrow{c_n}S_n,
\]

где \(S_i\) — состояние памяти, а \(c_i\) — очередная команда.

Основные понятия:

- переменная;
- присваивание;
- последовательность команд;
- условие;
- цикл;
- процедура и функция;
- локальная и глобальная память;
- побочный эффект.

Процедурная программа декомпозируется на подпрограммы, каждая из которых решает отдельную часть задачи.

### Fortran

Fortran исторически ориентирован на научные и инженерные вычисления. Характерные свойства:

- развитые числовые типы;
- многомерные массивы;
- операции над целыми массивами;
- функции и подпрограммы;
- модули;
- средства ввода-вывода;
- возможности распараллеливания и работы с массивными вычислениями.

Современный Fortran существенно отличается от ранних версий: он поддерживает модули, пользовательские типы, динамические массивы и элементы объектно-ориентированного программирования. Компилятор GNU Fortran является отдельным входным языковым модулем GCC, после которого используются общие оптимизирующие и машинно-зависимые стадии. ([gcc.gnu.org](https://gcc.gnu.org/onlinedocs/gfortran/GNU-Fortran-and-GCC.html?utm_source=openai))

### C

C создавался как язык системного программирования. Его характерные свойства:

- относительно небольшое ядро языка;
- эффективная трансляция в машинный код;
- явная работа с адресами через указатели;
- арифметика указателей;
- структуры и объединения;
- ручное управление динамической памятью;
- тесная связь с системными интерфейсами;
- раздельная компиляция.

Пример:

```c
int sum(const int *a, int n)
{
    int result = 0;
    for (int i = 0; i < n; ++i)
        result += a[i];
    return result;
}
```

Параметры в C передаются по значению. Изменение объекта вызывающей функции осуществляется посредством передачи его адреса:

```c
void increment(int *p)
{
    ++*p;
}
```

Язык C предоставляет функции, указатели на функции, массивы, структуры, области видимости и различные продолжительности хранения объектов. ([gnu.org](https://www.gnu.org/software/c-intro-and-ref/manual/c-intro-and-ref.html?utm_source=openai))



## 1.3. Функциональное программирование

В функциональном программировании вычисление рассматривается преимущественно как вычисление значений выражений и применение функций.

Основные свойства функционального стиля:

1. функции являются значениями первого класса;
2. функции могут передаваться как аргументы и возвращаться как результаты;
3. широко используются функции высшего порядка;
4. вместо циклов часто применяется рекурсия;
5. данные по возможности неизменяемы;
6. программы строятся композиционно;
7. важную роль играют сопоставление с образцом и алгебраические типы данных.

### Чистота и ссылочная прозрачность

Выражение называется **ссылочно прозрачным**, если его можно заменить вычисленным значением без изменения поведения программы.

Если

\[
f(x)=x^2,
\]

то каждое вычисление \(f(3)\) даёт одно и то же значение 9. Результат не зависит от скрытого состояния.

Чистая функция:

- не изменяет внешнее состояние;
- не выполняет скрытый ввод-вывод;
- при одинаковых аргументах возвращает одинаковый результат.

Не все функциональные языки являются чистыми. Например, Lisp и ML допускают изменяемые данные и побочные эффекты.

### LISP

LISP ориентирован на обработку символьной информации и списков.

Основные особенности:

- программы и данные имеют сходное списочное представление;
- функции являются объектами первого класса;
- широко применяется рекурсия;
- типизация в традиционных диалектах динамическая;
- развитая система макросов;
- автоматическое управление памятью;
- интерактивная среда разработки.

Пример:

```lisp
(defun factorial (n)
  (if (= n 0)
      1
      (* n (factorial (- n 1)))))
```

Списочное представление программы облегчает метапрограммирование: макрос получает синтаксическую конструкцию как структуру данных и формирует новую программу.

### ML

ML — функциональный язык со строгой статической типизацией и выводом типов.

Характерные свойства:

- энергичная, то есть не ленивая по умолчанию, стратегия вычислений;
- параметрический полиморфизм;
- алгебраические типы данных;
- сопоставление с образцом;
- функции высшего порядка;
- модули и сигнатуры;
- исключения;
- возможность использования ссылок и изменяемого состояния.

Пример:

```sml
fun factorial 0 = 1
  | factorial n = n * factorial (n - 1)
```

Standard ML сочетает функциональное программирование с императивными операциями, исключениями, полиморфной системой типов и развитой модульной системой. ([smlfamily.github.io](https://smlfamily.github.io/sml97-defn.pdf?utm_source=openai))

### Haskell

Haskell — чистый функциональный язык с нестрогими, обычно ленивыми, вычислениями.

Основные свойства:

- статическая типизация;
- вывод типов;
- алгебраические типы;
- сопоставление с образцом;
- функции высшего порядка;
- ленивые вычисления;
- классы типов;
- монады для описания последовательных вычислений и эффектов.

Пример:

```haskell
factorial 0 = 1
factorial n = n * factorial (n - 1)
```

Бесконечные структуры допустимы благодаря ленивому вычислению:

```haskell
naturals = [0..]
```

Элементы такого списка вычисляются только по мере необходимости. Стандарт Haskell определяет статическую семантику функций и образцов, модульную структуру, типы, классы типов, ленивые вычисления и представление ввода-вывода. ([haskell.org](https://www.haskell.org/onlinereport/haskell2010/?utm_source=openai))



## 1.4. Логическое программирование

Логическое программирование основывается на представлении знаний в виде логических утверждений.

Программа состоит из:

- фактов;
- правил;
- запросов.

Пример на Prolog:

```prolog
parent(anna, boris).
parent(boris, victor).

ancestor(X, Y) :-
    parent(X, Y).

ancestor(X, Y) :-
    parent(X, Z),
    ancestor(Z, Y).
```

Запрос:

```prolog
?- ancestor(anna, victor).
```

даёт ответ `true`.

### Декларативный смысл

Правило

```prolog
ancestor(X, Y) :- parent(X, Z), ancestor(Z, Y).
```

можно прочитать:

> \(X\) является предком \(Y\), если существует \(Z\), для которого \(X\) — родитель \(Z\), а \(Z\) — предок \(Y\).

Логическая программа в основном описывает, **какие отношения должны выполняться**, а не последовательность машинных команд.

### Унификация

Унификация — поиск подстановки, делающей два терма одинаковыми.

Например, термы

\[
parent(X,b)
\quad\text{и}\quad
parent(a,Y)
\]

унифицируются подстановкой

\[
\{X\mapsto a,\;Y\mapsto b\}.
\]

### Поиск решения

Для выполнения запроса Prolog применяет:

- выбор правил;
- унификацию;
- доказательство подцелей;
- возврат, или backtracking, при неудаче.

Если выбранное правило не приводит к решению, система отменяет соответствующие связывания переменных и пробует альтернативу. Именно backtracking является стандартным механизмом поиска Prolog. ([swi-prolog.org](https://www.swi-prolog.org/pldoc/man?section=glossary&utm_source=openai))

Практическое выполнение зависит от порядка правил и подцелей. Поэтому логически эквивалентные программы могут существенно различаться временем работы и завершимостью.



## 1.5. Объектно-ориентированные языки

Объектно-ориентированная программа строится как система взаимодействующих объектов.

Объект характеризуется:

- идентичностью;
- состоянием;
- поведением.

Основные понятия:

- класс;
- объект;
- инкапсуляция;
- наследование;
- интерфейс;
- полиморфизм;
- динамическое связывание методов.

### Java

Java — статически типизированный объектно-ориентированный язык. Обычно исходная программа транслируется в байт-код виртуальной машины JVM.

Характерные свойства:

- классы и интерфейсы;
- одиночное наследование классов;
- реализация нескольких интерфейсов;
- автоматическое управление памятью;
- исключения;
- обобщённые типы;
- динамическая загрузка классов;
- рефлексия;
- стандартная библиотека.

Спецификация Java отдельно определяет лексическую и контекстно-свободную грамматики, классы, интерфейсы, массивы, исключения и модель выполнения. ([docs.oracle.com](https://docs.oracle.com/en/java/javase/26/docs/specs/jls/index.html?utm_source=openai))

### C#

C# также является статически типизированным объектно-ориентированным языком управляемой платформы.

Характерные средства:

- классы и структуры;
- интерфейсы;
- свойства;
- события и делегаты;
- обобщённые типы;
- исключения;
- рефлексия;
- итераторы;
- асинхронные операции;
- сборка мусора.

Класс C# может наследоваться от одного базового класса и реализовывать несколько интерфейсов; интерфейс задаёт контракт, которому должен соответствовать реализующий его тип. ([learn.microsoft.com](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/language-specification/interfaces?utm_source=openai))



## 1.6. Сравнение парадигм

| Парадигма | Основная модель | Основные конструкции | Примеры |
|||||
| Процедурная | изменение состояния | присваивание, цикл, процедура | Fortran, C |
| Функциональная | вычисление выражений | функции, рекурсия, композиция | Lisp, ML, Haskell |
| Логическая | доказательство целей | факты, правила, унификация | Prolog |
| Объектная | взаимодействие объектов | классы, методы, интерфейсы | Java, C# |

Границы не абсолютны:

- C допускает функциональный стиль через указатели на функции;
- Lisp поддерживает изменение состояния и объектные расширения;
- ML сочетает функциональные и императивные средства;
- Java и C# поддерживают лямбда-выражения;
- Prolog может использоваться в алгоритмическом, а не только декларативном стиле.

# 2. Процедурные языки: данные, управление, процедуры и исключения

## 2.1. Структура процедурной программы

Процедурная программа обычно содержит:

1. объявления модулей и библиотек;
2. определения типов;
3. глобальные объявления;
4. определения функций и процедур;
5. главную программу;
6. локальные объявления и операторы.

Пример общей структуры:

```text
импорт библиотек

объявление типов
объявление глобальных объектов

процедура P(...)
    локальные переменные
    операторы
конец P

главная программа
    операторы
конец
```

Модульность позволяет:

- разделять интерфейс и реализацию;
- выполнять раздельную компиляцию;
- повторно использовать код;
- локализовать изменения.



## 2.2. Основные управляющие конструкции

Согласно теореме о структурном программировании, алгоритм можно строить из трёх основных конструкций:

1. последовательности;
2. ветвления;
3. итерации.

### Последовательность

```c
read_data();
result = calculate();
print_result(result);
```

### Условный оператор

```c
if (x >= 0)
    y = x;
else
    y = -x;
```

Обобщённый выбор:

```c
switch (operation) {
    case ADD: result = a + b; break;
    case SUB: result = a - b; break;
    default:  report_error();
}
```

### Циклы

Цикл с предусловием:

```c
while (condition) {
    body;
}
```

Цикл с постусловием:

```c
do {
    body;
} while (condition);
```

Счётный цикл:

```c
for (int i = 0; i < n; ++i) {
    body;
}
```

Дополнительные управляющие средства:

- `break` — выход из цикла;
- `continue` — переход к следующей итерации;
- `return` — выход из подпрограммы;
- `goto` — безусловный переход;
- вызов процедуры;
- возбуждение исключения.

Неограниченное применение `goto` усложняет построение и анализ графа управления, хотя сама конструкция не является принципиально некорректной.



## 2.3. Переменные, константы, область действия и время жизни

**Переменная** — именованный объект, значение которого может изменяться.

С переменной связаны:

- имя;
- тип;
- значение;
- адрес или место хранения;
- область видимости;
- время жизни;
- допустимые операции.

**Константа** — значение или именованный объект, изменение которого программой запрещено.

Следует различать:

- литерал: `42`, `'a'`, `3.14`;
- именованную константу;
- объект только для чтения;
- значение, вычисляемое на этапе компиляции.

### Область действия

**Область действия**, scope, определяет часть программы, в которой имя обозначает соответствующий объект.

Наиболее распространено лексическое правило: область определяется вложенностью блоков исходного текста.

```c
int x = 1;

void f(void)
{
    int x = 2;  /* скрывает внешнее x */
    {
        int y = x + 1;
    }
    /* y здесь не видна */
}
```

### Время жизни

Время жизни — интервал выполнения, в течение которого объект существует.

Типичные виды хранения:

- статическое — объект существует всё время работы программы;
- автоматическое — объект существует во время вызова блока или функции;
- динамическое — объект существует от выделения до освобождения памяти;
- потоковое — отдельная копия объекта для каждого потока.

Область действия имени и время жизни объекта — разные понятия. Объект может продолжать существовать после выхода имени из области видимости, например если на него сохранён указатель или ссылка.



## 2.4. Типы данных

Тип данных определяет:

- множество допустимых значений;
- представление значений;
- набор операций;
- правила совместимости и преобразований.

### Булевский тип

Содержит значения `истина` и `ложь`:

\[
Boolean=\{\mathrm{false},\mathrm{true}\}.
\]

Операции:

\[
\neg,\quad \land,\quad \lor,\quad \oplus.
\]

### Целочисленные типы

Характеризуются:

- знаковостью;
- диапазоном;
- разрядностью;
- правилами переполнения;
- допустимыми преобразованиями.

Переполнение может:

- давать результат по модулю;
- вызывать исключение;
- приводить к неопределённому поведению;
- обрабатываться средствами времени выполнения.

Конкретная семантика зависит от языка и типа.

### Типы с плавающей точкой

Число обычно представляется в форме

\[
x=(-1)^s\cdot m\cdot b^e,
\]

где \(s\) — знак, \(m\) — мантисса, \(b\) — основание, \(e\) — порядок.

Такие значения представляют конечное множество рациональных чисел, поэтому операции выполняются с округлением:

\[
fl(a+b)\ne a+b
\]

в общем случае.

Например, из-за округления ассоциативность может нарушаться:

\[
fl((a+b)+c)\ne fl(a+(b+c)).
\]

### Символьный и строковый типы

Символьный тип представляет отдельный знак некоторого набора символов.

Строка может быть представлена как:

- массив символов;
- объект с длиной;
- неизменяемая последовательность;
- последовательность кодовых единиц Unicode.

Символ, кодовая единица и графический знак не всегда совпадают.

### Диапазонный тип

Тип диапазона ограничивает значения некоторым интервалом:

\[
T=\{l,l+1,\ldots,r\}.
\]

Преимущество — возможность проверки границ и более точного выражения условий задачи.

### Перечислимый тип

```text
Color = (red, green, blue)
```

Значениями являются именованные константы. Перечисление позволяет отказаться от неинформативных числовых кодов.

### Указатели

Указатель хранит адрес объекта или специальное пустое значение.

Операции:

- получение адреса;
- разыменование;
- сравнение;
- арифметика указателей в языках низкого уровня;
- выделение и освобождение динамической памяти.

Ошибки:

- разыменование нулевого указателя;
- выход за границу объекта;
- висячий указатель;
- повторное освобождение;
- утечка памяти;
- использование неинициализированного указателя.



## 2.5. Массивы и записи

### Массив

Массив — индексированная совокупность элементов одного типа.

\[
A:L_1\times\cdots\times L_k\to T,
\]

где \(L_i\) — множество индексов, \(T\) — тип элемента.

Одномерный массив:

```c
int a[100];
```

Многомерный массив:

```c
double matrix[10][20];
```

Если элементы хранятся последовательно по строкам, адрес элемента двумерного массива имеет вид

\[
address(A[i,j])
=
base(A)+((i-l_1)N_2+(j-l_2))\cdot size(T).
\]

При хранении по столбцам формула меняется.

Описание массива может содержать:

- адрес данных;
- число измерений;
- границы;
- длины;
- шаги между элементами.

### Запись

Запись объединяет поля разных типов:

```c
struct Student {
    int id;
    char name[64];
    double grade;
};
```

Поля имеют имена и смещения относительно начала объекта:

\[
address(field_i)=address(record)+offset_i.
\]

Между полями может находиться выравнивающее заполнение. Структуры C являются составными типами, содержащими именованные поля, каждое из которых имеет собственный тип. ([gnu.org](https://www.gnu.org/software/c-intro-and-ref/manual/html_node/Structures.html?utm_source=openai))



## 2.6. Процедуры и функции

**Процедура** — именованная программная единица, которую можно вызвать из другой части программы.

**Функция** возвращает значение как результат вызова. В некоторых языках процедура и функция являются различными конструкциями, в других используется единое понятие функции.

При вызове обычно создаётся **активационная запись**, или кадр стека, содержащая:

- параметры;
- локальные переменные;
- адрес возврата;
- сохранённые регистры;
- временные значения;
- ссылку на вызывающий кадр;
- данные для доступа к нелокальным переменным.

После завершения вызова кадр обычно удаляется.



## 2.7. Способы передачи параметров

### Передача по значению

В формальный параметр помещается значение фактического аргумента.

```text
procedure P(x: integer)
    x := x + 1
end
```

Изменение `x` не изменяет переменную вызывающей стороны.

Преимущества:

- отсутствие непосредственного изменения аргумента;
- понятная локальная семантика;
- простота реализации.

Для крупных объектов копирование может быть дорогостоящим, хотя компилятор имеет право оптимизировать реализацию при сохранении семантики.

### Передача по ссылке

Формальный параметр обозначает тот же объект, что и фактический аргумент.

```text
procedure Swap(reference a, reference b)
```

Изменение формального параметра изменяет исходный объект.

Проблема — возможное наложение параметров:

```text
P(x, x)
```

Если оба формальных параметра ссылаются на один объект, результат может зависеть от порядка операций.

### Передача по результату

Формальный параметр рассматривается как локальная переменная процедуры. При завершении его значение копируется в фактический параметр:

```text
formal := local temporary
при возврате actual := formal
```

Начальное значение фактического параметра внутрь процедуры не передаётся.

Если несколько параметров по результату связаны с одним объектом, итог может зависеть от порядка обратного копирования.

### Передача по значению-результату

В начале вызова выполняется копирование внутрь, а в конце — копирование обратно:

\[
formal:=actual;
\]

после выполнения:

\[
actual:=formal.
\]

Эта семантика отличается от передачи по ссылке, если имеются псевдонимы или фактический параметр изменяется другим способом во время вызова.

### В языке C

В C все аргументы передаются по значению. Передача указателя означает копирование значения указателя, после чего функция может изменить адресуемый объект. Это не изменяет самого правила передачи параметров.



## 2.8. Побочные эффекты

**Побочный эффект** — изменение состояния, не являющееся непосредственно вычисленным значением выражения.

Примеры:

- изменение переменной;
- запись в файл;
- вывод на экран;
- изменение объекта через указатель;
- выделение памяти;
- возбуждение исключения;
- синхронизация потоков.

Пример:

```c
int counter = 0;

int next(void)
{
    return ++counter;
}
```

Вызов `next()` не только возвращает значение, но и изменяет `counter`.

Побочные эффекты усложняют:

- понимание программы;
- оптимизацию;
- параллельное выполнение;
- тестирование;
- доказательство корректности.

Особенно опасно сочетание нескольких неупорядоченных побочных эффектов над одним объектом.



## 2.9. Исключительные ситуации

Исключение — механизм передачи управления при обнаружении ситуации, не обрабатываемой обычным продолжением вычисления.

Общая конструкция:

```text
try
    опасная операция
catch E1
    обработка E1
catch E2
    обработка E2
finally
    освобождение ресурсов
end
```

Основные этапы:

1. создание или выбор объекта исключения;
2. возбуждение исключения;
3. поиск подходящего обработчика;
4. раскрутка стека;
5. освобождение локальных ресурсов;
6. передача управления обработчику.

Если обработчик не найден, программа или поток обычно завершается.

Исключения подразделяют на:

- синхронные — связаны с текущей операцией;
- асинхронные — вызваны внешним событием;
- проверяемые статически;
- непроверяемые;
- системные;
- пользовательские.

Java, например, определяет виды исключений, их причины, статическую проверку некоторых исключений и порядок обработки во время выполнения. ([docs.oracle.com](https://docs.oracle.com/en/java/javase/26/docs/specs/jls/index.html?utm_source=openai))

Исключение не следует использовать как замену обычному условному переходу в ожидаемой ситуации. Его основное назначение — отделить нормальный алгоритм от обработки ошибок.



## 2.10. Библиотеки процедур

**Библиотека** — организованный набор программных компонентов с документированным интерфейсом.

Виды библиотек:

- исходные;
- статические;
- динамические;
- стандартные;
- сторонние;
- системные.

### Статическое связывание

Код требуемых процедур включается в исполняемый файл компоновщиком.

Преимущества:

- меньше зависимостей при запуске;
- предсказуемость версии.

Недостатки:

- увеличение размера;
- отдельная копия кода в каждом файле;
- необходимость перекомпоновки для обновления.

### Динамическое связывание

Код библиотеки загружается отдельно во время запуска или по требованию.

Преимущества:

- совместное использование кода;
- возможность обновления библиотеки;
- меньший размер исполняемых файлов.

Недостатки:

- проблемы совместимости версий;
- необходимость поиска библиотеки;
- возможная ошибка при загрузке.

Использование библиотеки включает:

1. подключение объявления интерфейса;
2. компиляцию вызовов;
3. разрешение внешних имён компоновщиком или загрузчиком;
4. выполнение библиотечного кода.

# 3. Статическая и динамическая типизация. Сильная и слабая типизация. Языки сценариев

## 3.1. Система типов

Система типов классифицирует значения и выражения и устанавливает правила допустимости операций.

Она предназначена для:

- обнаружения ошибок;
- документирования интерфейсов;
- выбора представления данных;
- разрешения перегрузки;
- поддержки оптимизации;
- обеспечения безопасности памяти;
- организации абстракций.



## 3.2. Статическая типизация

При статической типизации существенная часть типовых проверок выполняется до запуска программы.

Пример:

```java
int x = 10;
x = "text";       // ошибка компиляции
```

Тип выражения определяется из:

- объявлений;
- контекста;
- правил вывода типов;
- ограничений параметров типов.

### Явное объявление

```c
double x;
```

### Вывод типа

```text
x = 10
```

Компилятор может вывести, что `x` имеет целочисленный тип.

Статическая типизация не означает обязательного явного указания всех типов. ML и Haskell являются статически типизированными языками с развитым выводом типов. Standard ML сочетает сильную типизацию с полиморфным выводом типов, а Haskell определяет статическую семантику функциональных объявлений и типовых классов. ([smlfamily.github.io](https://smlfamily.github.io/sml97-defn.pdf?utm_source=openai))

Преимущества:

- раннее обнаружение ошибок;
- эффективная генерация кода;
- удобство рефакторинга;
- документирование интерфейсов;
- возможность статического анализа.

Недостатки:

- необходимость формулировать типовые ограничения;
- более сложная система языка;
- не все свойства удобно выражаются статически.



## 3.3. Динамическая типизация

При динамической типизации тип связан прежде всего со значением, а допустимость операции проверяется при выполнении.

```python
x = 10
x = "text"
```

Одна переменная может последовательно ссылаться на значения разных типов.

Преимущества:

- краткость программ;
- гибкость структур данных;
- удобство интерактивной разработки;
- простое создание обобщённого кода;
- удобство прототипирования.

Недостатки:

- часть ошибок проявляется только при выполнении;
- требуется больше тестирования;
- сложнее глобальный статический анализ;
- возможны дополнительные проверки и диспетчеризация во время работы.

Примеры динамически типизированных языков:

- Lisp;
- Python;
- JavaScript;
- Ruby;
- большинство реализаций Prolog.

Динамическая типизация не означает отсутствие типов: каждое значение имеет тип, но проверка выполняется позже.



## 3.4. Постепенная типизация

**Постепенная типизация**, gradual typing, сочетает статически проверяемые и динамические части.

Программист может аннотировать типы только там, где это необходимо:

```text
def add(x: int, y: int) -> int:
    return x + y
```

Граница между статической и динамической частями может потребовать выполнения проверок во время работы.



## 3.5. Сильная и слабая типизация

Термины «сильная» и «слабая типизация» не имеют единого строго стандартизованного определения. Обычно под **сильной типизацией** понимают систему, которая не допускает неявного смешения семантически несовместимых типов и не позволяет произвольно интерпретировать значение как объект другого типа.

Признаки более сильной типизации:

- отсутствие неявного преобразования строки в число;
- невозможность сложить указатель и строку;
- проверка границ и представлений;
- ограниченные преобразования между несвязанными типами;
- отсутствие произвольного доступа к памяти.

Пример сильной динамической типизации:

```python
1 + "2"       # ошибка типа
```

Динамичность не означает слабость: Python динамически, но сравнительно сильно типизирован.

Признаки относительно слабой типизации:

- многочисленные неявные преобразования;
- возможность трактовать участок памяти как объект другого типа;
- арифметика необработанных адресов;
- преобразование между несовместимыми указателями;
- смешение логических и числовых значений.

C часто называют относительно слабо типизированным из-за неявных арифметических преобразований, указателей и явных приведений. Однако C всё же имеет развитую статическую систему типов и правила совместимости типов. ([gnu.org](https://www.gnu.org/software/c-intro-and-ref/manual/c-intro-and-ref.html?utm_source=openai))

### Типовые примеры

| Язык | Время основной проверки | Характер типизации |
||||
| Haskell | до исполнения | сильная статическая |
| ML | до исполнения | сильная статическая |
| Java | преимущественно до исполнения | сильная статическая |
| C# | преимущественно до исполнения | сильная статическая |
| C | до исполнения | статическая, сравнительно слабая |
| Python | во время исполнения | сильная динамическая |
| JavaScript | во время исполнения | динамическая с широкими преобразованиями |
| Lisp | во время исполнения | динамическая |

Эта таблица отражает общепринятую практическую классификацию, но «сила» типизации представляет скорее спектр, чем бинарное свойство.



## 3.6. Номинативная и структурная совместимость

### Номинативная типизация

Типы совместимы на основании объявленных имён и отношений:

```text
class B extends A
```

Объект `B` можно использовать как `A`, поскольку отношение наследования объявлено явно.

### Структурная типизация

Совместимость определяется структурой типа: набором полей и операций.

Если объект имеет требуемую операцию `read`, он может использоваться в соответствующем контексте независимо от имени его класса.

С динамической структурной типизацией связывают термин **duck typing**: допустимость объекта определяется поддерживаемыми им операциями.



## 3.7. Языки сценариев

Язык сценариев первоначально предназначался для:

- автоматизации действий;
- управления другими программами;
- обработки файлов;
- настройки систем;
- связывания компонентов;
- выполнения команд в интерактивной среде.

Примеры:

- командные оболочки;
- Python;
- Perl;
- JavaScript;
- Lua;
- Ruby;
- языки командных файлов.

Типичные, но не обязательные свойства:

- быстрое выполнение исходного текста без отдельной ручной компоновки;
- динамическая типизация;
- автоматическое управление памятью;
- богатые строковые средства;
- встроенная работа с файлами и процессами;
- интерактивный режим;
- развитые библиотеки;
- переносимость;
- возможность вызова компонентов, написанных на других языках.

Термин «сценарный язык» описывает скорее способ применения и среду, чем строгую вычислительную модель. Сценарный язык может компилироваться в байт-код или машинный код, а язык общего назначения может использоваться для написания сценариев.

# 4. Объектно-ориентированное программирование

## 4.1. Объект

**Объект** — сущность, обладающая:

1. идентичностью;
2. состоянием;
3. поведением.

Состояние определяется значениями полей. Поведение задаётся методами.

Два объекта могут иметь одинаковые поля, но оставаться различными объектами:

\[
o_1\ne o_2,\qquad state(o_1)=state(o_2).
\]



## 4.2. Класс

**Класс** — описание множества объектов с общей структурой и поведением.

Класс обычно определяет:

- поля;
- методы;
- конструкторы;
- свойства;
- допустимые операции;
- инварианты;
- уровни доступа.

Пример:

```java
class Account {
    private int balance;

    Account(int initial) {
        if (initial < 0)
            throw new IllegalArgumentException();
        balance = initial;
    }

    public void deposit(int amount) {
        if (amount <= 0)
            throw new IllegalArgumentException();
        balance += amount;
    }

    public int getBalance() {
        return balance;
    }
}
```

Инвариант:

\[
balance\geq0.
\]

Инкапсуляция не сводится к сокрытию полей. Её цель — разрешить изменение состояния только через операции, сохраняющие инварианты.



## 4.3. Инкапсуляция

**Инкапсуляция** объединяет состояние и операции над ним и скрывает детали реализации.

Типичные уровни доступа:

- открытый;
- защищённый;
- пакетный или внутренний;
- закрытый.

Преимущества:

- локализация изменений;
- защита инвариантов;
- уменьшение связанности;
- возможность заменить представление объекта без изменения клиентов.



## 4.4. Наследование

Наследование позволяет определить новый класс на основе существующего.

```text
class SavingsAccount extends Account
```

Производный класс получает доступные члены базового класса и может:

- добавлять новые поля;
- добавлять методы;
- переопределять виртуальные методы;
- уточнять поведение.

Следует различать:

1. **наследование реализации** — повторное использование кода;
2. **подтипирование** — возможность использовать объект производного типа там, где ожидается базовый.

Корректное подтипирование должно сохранять контракт базового типа. В частности, производный класс не должен нарушать существенные свойства, на которые рассчитывает клиент базового класса.

Наследование может создавать сильную связь между классами. Поэтому повторное использование поведения часто реализуют через **композицию**:

```text
class Car {
    Engine engine;
}
```

Принцип:

> композицию следует предпочитать наследованию, если отношение «является разновидностью» отсутствует.



## 4.5. Полиморфизм

Полиморфизм означает возможность работать с объектами разных конкретных типов через общий интерфейс.

### Полиморфизм подтипов

```java
Shape s = new Circle();
s.draw();
```

Вызывается реализация `draw`, соответствующая фактическому классу `Circle`.

### Динамическая диспетчеризация

Конкретный метод выбирается во время выполнения на основе динамического типа объекта.

Упрощённо объект может содержать ссылку на таблицу виртуальных методов:

```text
объект → таблица методов → реализации
```

### Параметрический полиморфизм

Обобщённый контейнер:

```text
List<T>
```

работает с различными типами элементов, не переписывая алгоритм для каждого типа.

### Перегрузка

Несколько методов имеют одно имя, но разные сигнатуры:

```text
print(int)
print(string)
```

Обычно вариант перегрузки выбирается статически. Поэтому перегрузку не следует смешивать с виртуальным переопределением.



## 4.6. Интерфейсы

**Интерфейс** задаёт контракт: набор операций, которые должен предоставлять объект.

```java
interface Drawable {
    void draw();
}
```

Интерфейс позволяет:

- отделить спецификацию от реализации;
- уменьшить зависимость от конкретного класса;
- применять полиморфизм;
- имитировать множественное наследование типов;
- заменять реализации;
- создавать тестовые объекты.

Класс может реализовывать несколько интерфейсов:

```java
class Window implements Drawable, Closeable
```

C# также разрешает классу или структуре реализовывать несколько интерфейсов; интерфейс определяет контракт, а конкретная реализация предоставляется типом или унаследованным интерфейсом. ([learn.microsoft.com](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/language-specification/interfaces?utm_source=openai))

### Интерфейс и абстрактный класс

| Интерфейс | Абстрактный класс |
|||
| прежде всего задаёт контракт | может содержать общее состояние |
| поддерживает множественную реализацию интерфейсов | класс обычно имеет одного базового класса |
| ослабляет связанность | удобен для общего кода и полей |
| не должен навязывать представление | может задавать частичную реализацию |



## 4.7. Объектное окружение

Термин **объектное окружение** используется в нескольких близких значениях.

В широком смысле это совокупность средств времени выполнения, обеспечивающих существование и взаимодействие объектов:

- объектная память, или куча;
- метаданные классов;
- таблицы методов;
- загрузчик классов;
- диспетчеризация вызовов;
- сборщик мусора;
- система исключений;
- библиотеки классов;
- механизмы рефлексии;
- средства синхронизации;
- пространства имён и модули.

В более узком смысле окружением объекта называют доступную ему совокупность:

- других объектов;
- сервисов;
- переменных и связываний;
- контекста исполнения;
- ссылок, по которым объект может взаимодействовать с системой.

Графически объектная программа может быть представлена ориентированным графом:

\[
G=(O,R),
\]

где \(O\) — объекты, \(R\) — ссылки между ними.

Объекты, достижимые от корней программы, считаются живыми. Недостижимые объекты могут быть освобождены сборщиком мусора.



## 4.8. Рефлексия

**Рефлексия** — способность программы исследовать и в некоторых системах изменять собственную структуру во время выполнения.

Рефлексия позволяет:

- получить динамический класс объекта;
- перечислить методы и поля;
- исследовать аннотации и атрибуты;
- создать объект по имени класса;
- вызвать метод по имени;
- загрузить модуль;
- построить сериализатор;
- реализовать контейнер зависимостей;
- создавать отладчики и тестовые системы.

В Java экземпляры `Class` представляют классы и интерфейсы загруженного приложения, а пакет `java.lang.reflect` предоставляет операции исследования конструкторов, методов и полей. ([docs.oracle.com](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/lang/reflect/package-summary.html?utm_source=openai))

Недостатки рефлексии:

- часть ошибок переносится на время выполнения;
- возможны затраты на поиск и вызов;
- усложняется статический анализ;
- нарушается инкапсуляция;
- динамически используемый код труднее удалить при оптимизации;
- возникают дополнительные риски безопасности.



## 4.9. Библиотеки классов

Библиотека классов предоставляет повторно используемые абстракции:

- строки;
- коллекции;
- файлы и потоки;
- сеть;
- графический интерфейс;
- многопоточность;
- сериализацию;
- базы данных;
- математические операции.

Правильный интерфейс библиотеки должен обеспечивать:

- ясный контракт;
- устойчивость к изменению реализации;
- обработку ошибок;
- управление ресурсами;
- совместимость версий;
- минимальную зависимость клиента от внутренних деталей.



## 4.10. Контейнеры

**Контейнер** хранит набор объектов и предоставляет операции над ними.

Основные контейнеры:

- массив;
- динамический массив;
- связный список;
- стек;
- очередь;
- множество;
- ассоциативный массив;
- дерево;
- приоритетная очередь.

Обобщённый контейнер:

```text
List<T>
Map<K,V>
Set<T>
```

Свойства контейнера задаются:

- допустимыми элементами;
- порядком;
- возможностью повторений;
- сложностью операций;
- правилами владения элементами;
- поведением при изменении во время обхода.



## 4.11. Итераторы

**Итератор** — объект, обеспечивающий последовательный доступ к элементам контейнера без раскрытия его внутреннего представления.

Типичный интерфейс:

```text
hasNext()
next()
```

Пример:

```java
Iterator<Item> it = collection.iterator();

while (it.hasNext()) {
    Item x = it.next();
    process(x);
}
```

Итератор отделяет:

- алгоритм обхода;
- структуру контейнера;
- обработку элементов.

Возможны:

- внешние итераторы — клиент явно вызывает `next`;
- внутренние итераторы — контейнер сам вызывает функцию обработки;
- ленивые итераторы — следующий элемент вычисляется по требованию;
- асинхронные итераторы.

В C# итераторный метод создаёт объект-перечислитель, а тело метода выполняется по мере вызовов операций продвижения. ([learn.microsoft.com](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/language-specification/classes?utm_source=openai))



## 4.12. Сопроцедуры

**Сопроцедура**, coroutine, — обобщение подпрограммы, которое может:

- приостановить выполнение;
- сохранить локальное состояние;
- передать управление;
- позднее продолжить работу с места остановки.

Обычная функция имеет одну точку входа и после возврата завершает активацию. Сопроцедура допускает многократное возобновление.

Пример генератора:

```text
generator numbers(n):
    for i = 1 to n:
        yield i
```

При `yield`:

- возвращается очередное значение;
- сохраняются локальные переменные;
- запоминается позиция;
- при следующем запросе выполнение продолжается.

Применения:

- генераторы последовательностей;
- кооперативная многозадачность;
- асинхронный ввод-вывод;
- обработка событий;
- потоковая обработка данных;
- реализация итераторов.

# 5. Машинно-ориентированные языки и язык ассемблера

## 5.1. Машинный язык

Машинная программа — последовательность команд, непосредственно распознаваемых процессором.

Машинная команда обычно содержит:

\[
\text{код операции}
+
\text{описание операндов}.
\]

Поля команды могут включать:

- opcode;
- номера регистров;
- режим адресации;
- непосредственную константу;
- смещение;
- признак размера;
- условие выполнения.

Пример условного формата:

```text
| opcode | rd | rs1 | rs2 | function |
```

или

```text
| opcode | register | immediate |
```

В архитектурах с фиксированной длиной команды поля обычно расположены в заранее определённых позициях. В архитектурах с переменной длиной команда может включать префиксы, байт операции, описание адресации и непосредственные данные.



## 5.2. Язык ассемблера

Ассемблер заменяет двоичные коды символическими обозначениями.

Машинная команда:

```text
10110000 00000101
```

может быть записана символически:

```asm
mov r0, 5
```

Строка программы обычно содержит:

```text
метка:  мнемоника  операнды   комментарий
```

Пример:

```asm
loop:
    add r1, r1, r2
    sub r3, r3, 1
    bne r3, zero, loop
```

Ассемблер предоставляет:

- символические имена команд;
- имена регистров;
- метки;
- символические константы;
- выражения;
- директивы;
- макросы;
- условную трансляцию.

Синтаксис конкретного ассемблера зависит от архитектуры и инструментальной системы.



## 5.3. Представление констант

Константы могут записываться:

- в десятичной форме;
- в двоичной форме;
- в восьмеричной форме;
- в шестнадцатеричной форме;
- как символы и строки;
- как адресные выражения.

Примеры:

```asm
42
0x2A
0b101010
'A'
"hello"
label + 8
```

Размещение данных задаётся директивами:

```asm
.byte  1, 2, 3
.short 1000
.long  123456
.ascii "text"
.asciz "text"
```

При формировании многобайтовой константы учитываются:

- разрядность;
- порядок байтов;
- выравнивание;
- формат числа с плавающей точкой;
- формат объектного файла.



## 5.4. Символы и метки

Метка связывает имя с текущим значением счётчика адреса:

```asm
start:
```

Ассемблер помещает в таблицу символов соответствие:

\[
start\longrightarrow address.
\]

Символы могут быть:

- определёнными;
- неопределёнными внешними;
- локальными;
- глобальными;
- абсолютными;
- связанными с секцией.

При ссылке вперёд:

```asm
    jump finish
    ...
finish:
```

значение `finish` ещё неизвестно в момент чтения первой команды. Оно разрешается на последующей стадии либо оформляется как запись перемещения.



## 5.5. Секции и перемещения

Объектный файл обычно содержит секции:

- код;
- инициализированные данные;
- неизменяемые данные;
- неинициализированные данные;
- таблицу символов;
- информацию о перемещениях;
- отладочную информацию.

Пример:

```asm
.text
.global function

function:
    ...

.data
value:
    .long 10
```

Если окончательный адрес символа неизвестен, ассемблер формирует **запись перемещения**, relocation entry. Компоновщик после размещения секций корректирует поле команды или данных.

Запись перемещения содержит:

- место исправления;
- используемый символ;
- вид перемещения;
- добавочное значение;
- правила вычисления результата.

Например, значение может вычисляться как

\[
S+A
\]

или для относительного перехода:

\[
S+A-P,
\]

где \(S\) — адрес символа, \(A\) — добавка, \(P\) — адрес исправляемого места.



## 5.6. Директивы ассемблера

**Директива**, или псевдооперация, управляет процессом трансляции. Она не обязательно соответствует машинной команде.

Основные группы директив:

### Управление секциями

```asm
.text
.data
.bss
.section
```

### Размещение данных

```asm
.byte
.short
.long
.ascii
.asciz
.space
```

### Выравнивание

```asm
.align
.balign
```

### Работа с символами

```asm
.global
.local
.extern
.type
.size
.equ
.set
```

### Подключение файлов

```asm
.include
.incbin
```

### Макросы и условия

```asm
.macro
.endm
.if
.else
.endif
```

### Отладочная и служебная информация

- номера строк;
- описание процедур;
- сведения о раскрутке стека;
- привязка к исходному файлу.

GNU `as` различает метки, инструкции и директивы; универсальные директивы имеют имена, обычно начинающиеся с точки. ([sourceware.org](https://sourceware.org/binutils/docs/as/Pseudo-Ops.html?utm_source=openai))



## 5.7. Принципы реализации ассемблера

Классическая схема двухпроходного ассемблера:

### Первый проход

1. Установить счётчик адреса в начало секции.
2. Считывать операторы.
3. Для меток запоминать текущее значение счётчика.
4. По длине команды или данных изменять счётчик.
5. Обрабатывать определения констант и секций.
6. Формировать таблицу символов.

### Второй проход

1. Повторно прочитать программу.
2. Найти код каждой команды.
3. Вычислить операнды.
4. Подставить известные адреса.
5. Сформировать записи перемещения для внешних или ещё не размещённых символов.
6. Записать объектный файл.

Современный ассемблер может быть однопроходным в организационном смысле, но тогда он хранит цепочки неразрешённых ссылок или создаёт записи перемещения для последующей обработки.

Основные таблицы:

- таблица операций;
- таблица символов;
- таблица секций;
- таблица литералов;
- таблица перемещений.



## 5.8. Макросредства

**Макрос** — параметризованный шаблон текста программы, разворачиваемый во время трансляции.

Определение:

```asm
.macro increment reg
    add \reg, \reg, 1
.endm
```

Вызов:

```asm
increment r5
```

Результат макрорасширения:

```asm
add r5, r5, 1
```

Макрос может иметь:

- позиционные параметры;
- именованные параметры;
- значения по умолчанию;
- переменное число аргументов;
- локальные метки;
- вложенные вызовы;
- условные части;
- циклическую генерацию.

GNU Assembler использует директивы `.macro` и `.endm` для определения макросов и поддерживает параметры и условное формирование текста. ([sourceware.org](https://www.sourceware.org/binutils/docs/as/Macro.html?utm_source=openai))



## 5.9. Макрос и процедура

| Макрос | Процедура |
|||
| раскрывается при трансляции | вызывается при выполнении |
| не требует машинной команды вызова | требует перехода и возврата |
| может увеличить размер кода | одна копия кода обслуживает вызовы |
| параметры подставляются синтаксически | параметры передаются согласно соглашению вызова |
| может создавать разные последовательности команд | тело процедуры фиксировано |
| ошибки относятся к раскрытому тексту | отлаживается как самостоятельная единица |

Макрос не является обычной функцией: он преобразует программу, а не выполняет вычисление во время работы.



## 5.10. Реализация макрогенератора

Макропроцессор хранит:

- таблицу имён макросов;
- тела макроопределений;
- формальные параметры;
- значения по умолчанию;
- информацию о локальных именах.

При макровызове:

1. находится определение макроса;
2. фактические параметры связываются с формальными;
3. создаётся контекст расширения;
4. параметры подставляются в тело;
5. локальные метки переименовываются;
6. обрабатываются условные конструкции;
7. результат возвращается во входной поток транслятора;
8. вложенные макровызовы раскрываются рекурсивно.

Локальные метки должны получать уникальные имена, иначе два раскрытия создадут конфликт.



## 5.11. Условная макрогенерация

Условная трансляция выбирает часть программы во время сборки:

```asm
.if DEBUG
    call print_debug_info
.endif
```

Условие вычисляется транслятором, а не выполняемой программой.

Применения:

- различные архитектуры;
- отладочная и рабочая сборки;
- выбор размера данных;
- включение аппаратных расширений;
- конфигурирование встроенных систем.

GNU `as` предоставляет директивы `.if`, `.else`, `.elseif` и `.endif`; исключённая ветвь не попадает в объектный код. ([sourceware.org](https://sourceware.org/binutils/docs/as.html?utm_source=openai))

# 6. Основы построения трансляторов и промежуточные представления

## 6.1. Виды трансляторов

**Транслятор** преобразует программу из одного языка в другой.

Основные виды:

- компилятор;
- ассемблер;
- препроцессор;
- транспилятор;
- компоновщик;
- загрузчик;
- JIT-компилятор.

Интерпретатор непосредственно выполняет программу или её промежуточное представление. На практике компиляция и интерпретация могут сочетаться.



## 6.2. Общая структура компилятора

```text
исходная программа
        ↓
лексический анализ
        ↓
синтаксический анализ
        ↓
семантический анализ
        ↓
промежуточное представление
        ↓
машинно-независимая оптимизация
        ↓
генерация машинного кода
        ↓
машинно-зависимая оптимизация
        ↓
объектная программа
```

Через все стадии проходят:

- таблица символов;
- система диагностики;
- информация о типах;
- координаты исходного текста.



## 6.3. Front end, middle end и back end

### Входная часть

Зависит от исходного языка и выполняет:

- лексический анализ;
- синтаксический анализ;
- статическую семантическую проверку;
- построение AST;
- формирование начального IR.

### Средняя часть

В значительной степени независима от исходного языка и целевой машины:

- строит граф управления;
- анализирует поток данных;
- выполняет SSA-преобразования;
- удаляет избыточные вычисления;
- оптимизирует циклы;
- выполняет межпроцедурный анализ.

### Выходная часть

Зависит от целевой архитектуры:

- выбирает машинные команды;
- распределяет регистры;
- планирует команды;
- реализует соглашение вызовов;
- размещает данные;
- генерирует объектный код.

GCC, например, имеет несколько языковых входных модулей, преобразующих программу в общие представления, общую оптимизирующую часть и машинно-зависимые выходные модули. ([gcc.gnu.org](https://gcc.gnu.org/onlinedocs/gfortran/GNU-Fortran-and-GCC.html?utm_source=openai))



## 6.4. Последовательность символов

Исходная программа сначала представляет собой последовательность символов:

```text
total = price * count;
```

На этом уровне учитываются:

- кодировка;
- переводы строк;
- комментарии;
- пробельные символы;
- экранирование;
- соединение строк;
- директивы препроцессора.

Это наиболее конкретное представление исходного текста.



## 6.5. Последовательность лексем

Лексический анализатор преобразует символы в токены:

```text
IDENT(total)
ASSIGN
IDENT(price)
MUL
IDENT(count)
SEMICOLON
```

Токен содержит:

- категорию;
- лексему;
- атрибут;
- координаты исходного текста.

Например, для целой константы атрибутом может быть уже преобразованное числовое значение, а для идентификатора — ссылка на запись таблицы символов.



## 6.6. Синтаксическое дерево

Синтаксическое дерево отражает вывод по грамматике.

Для грамматики

\[
E\to E+T\mid T,
\]

\[
T\to T*F\mid F,
\]

\[
F\to id\mid number
\]

дерево для `a + b * c` содержит нетерминалы \(E,T,F\), идентификаторы и знаки операций.

Синтаксическое дерево подробно отражает грамматику, но может содержать большое количество служебных узлов.



## 6.7. Абстрактное синтаксическое дерево

AST сохраняет семантически существенную структуру и удаляет:

- служебные нетерминалы;
- скобки;
- разделители;
- синтаксически вспомогательные узлы.

Для выражения

```text
a + b * c
```

AST:

```text
       +
      / \
     a   *
        / \
       b   c
```

AST удобно использовать для:

- проверки типов;
- интерпретации;
- генерации IR;
- статического анализа;
- рефакторинга.

Следует различать:

- concrete syntax tree — полное дерево разбора;
- abstract syntax tree — сокращённое семантическое дерево.



## 6.8. Высокоуровневое промежуточное представление

Высокоуровневый IR близок к исходному языку.

Он может сохранять:

- циклы `for`;
- условные выражения;
- объекты и методы;
- массивы;
- исключения;
- области видимости;
- типы высокого уровня;
- операции над целыми структурами.

Преимущества:

- удобно выполнять языковые оптимизации;
- сохраняется связь с исходным текстом;
- проще анализировать высокоуровневые конструкции.

Недостаток: сложно непосредственно отображать на машинные команды.



## 6.9. Среднеуровневое представление

Средний IR обычно содержит:

- базовые блоки;
- явные переходы;
- простые операции;
- временные переменные;
- обращения к памяти;
- вызовы;
- SSA-имена.

Он достаточно абстрактен для машинно-независимых оптимизаций, но уже не зависит от синтаксиса исходного языка.

Пример трёхадресного кода:

```text
t1 = b * c
t2 = a + t1
x  = t2
```

В трёхадресной команде обычно присутствует не более одной элементарной операции.



## 6.10. Низкоуровневое представление

Низкоуровневый IR близок к машинной архитектуре:

- виртуальные регистры;
- загрузки и сохранения;
- размеры операндов;
- явные условия переходов;
- операции, близкие к машинным;
- информация о соглашении вызовов.

Пример:

```text
v1 = load [b]
v2 = load [c]
v3 = mul.i32 v1, v2
v4 = load [a]
v5 = add.i32 v4, v3
store [x], v5
```

LLVM IR является типизированным представлением, основанным на SSA; оно имеет текстовую, двоичную и внутрипамятную формы. ([llvm.org](https://www.llvm.org/docs/LangRef.html?utm_source=openai))



## 6.11. Формы промежуточного представления

### Постфиксная запись

\[
a+b\cdot c
\]

представляется как

```text
a b c * +
```

Она удобна для стековой машины.

### Дерево

Выражение представляется иерархически. Хорошо отражает структуру, но не всегда удобно для общего использования подвыражений.

### Ориентированный ациклический граф

Одинаковые подвыражения могут быть представлены общим узлом.

Например:

\[
a+b\cdot c+d+b\cdot c
\]

содержит одно вычисление \(b\cdot c\), используемое дважды.

### Трёхадресный код

```text
t1 = b * c
t2 = a + t1
```

Формы хранения:

#### Четвёрки

\[
(op,arg_1,arg_2,result).
\]

Пример:

```text
(*, b, c, t1)
(+, a, t1, t2)
```

#### Тройки

Результат задаётся номером команды:

```text
0: (*, b, c)
1: (+, a, (0))
```

#### Косвенные тройки

Используется отдельный список указателей на тройки, что облегчает перестановку команд.

### Граф потока управления

Вершинами являются базовые блоки, рёбрами — возможные переходы управления.

### SSA

Каждая переменная определяется ровно один раз; разные присваивания получают разные версии.



## 6.12. Свойства хорошего IR

Промежуточное представление должно:

- иметь однозначную семантику;
- быть удобно для анализа;
- позволять выражать разные исходные языки;
- не зависеть чрезмерно от одной машины;
- сохранять типы и координаты;
- явно представлять управление и эффекты;
- облегчать преобразование в целевой код.

Единственного универсального IR обычно недостаточно. Поэтому компилятор последовательно понижает представление:

\[
HIR\longrightarrow MIR\longrightarrow LIR\longrightarrow machine\ code.
\]

# 7. Анализ исходной программы в компиляторе

## 7.1. Лексический анализ

Лексический анализатор преобразует поток символов в поток токенов.

Например:

```c
sum = a12 + 25;
```

преобразуется в:

```text
IDENT(sum)
ASSIGN
IDENT(a12)
PLUS
INTEGER(25)
SEMICOLON
```

Лексический анализатор:

- пропускает пробелы и комментарии;
- распознаёт идентификаторы и ключевые слова;
- преобразует константы;
- сообщает о недопустимых символах;
- хранит координаты токена;
- взаимодействует с таблицей символов.



## 7.2. Регулярные грамматики и конечные автоматы

Большинство лексем задаётся регулярными выражениями:

```text
letter = [A-Za-z_]
digit  = [0-9]

identifier = letter(letter|digit)*
integer    = digit+
```

Теоретическая схема построения сканера:

\[
\text{регулярное выражение}
\to
\varepsilon\text{-НКА}
\to
\text{ДКА}
\to
\text{таблица переходов или код}.
\]

Алгоритм Томпсона строит НКА. Метод подмножеств преобразует НКА в ДКА. Затем автомат может быть минимизирован или сжат.

### Максимальная лексема

Обычно выбирается самое длинное продолжение, соответствующее какому-либо правилу.

Например:

```text
<=
```

должно распознаваться как один оператор, а не как `<` и `=`.

Если несколько правил распознали одинаково длинную строку, применяется заданный приоритет. Flex принимает описание в виде регулярных выражений с действиями и генерирует функцию сканера. ([ftp.gnu.org](https://ftp.gnu.org/old-gnu/Manuals/flex-2.5.4/html_node/flex_4.html?utm_source=openai))



## 7.3. Контекстно-свободная грамматика

Грамматика задаётся четвёркой

\[
G=(N,\Sigma,P,S),
\]

где:

- \(N\) — нетерминалы;
- \(\Sigma\) — терминалы;
- \(P\) — продукции;
- \(S\) — начальный символ.

Контекстно-свободная продукция имеет вид

\[
A\to\alpha,
\]

где \(A\in N\), а \(\alpha\in(N\cup\Sigma)^*\).

Пример:

\[
E\to E+T\mid T,
\]

\[
T\to T*F\mid F,
\]

\[
F\to (E)\mid id.
\]

Контекстно-свободная грамматика позволяет описывать рекурсивные структуры, например вложенные скобки, которые нельзя в общем случае распознать конечным автоматом.



## 7.4. Таблица символов

Таблица символов хранит информацию об именах программы.

Запись может содержать:

- имя;
- категорию: переменная, функция, тип, поле;
- тип;
- область действия;
- адрес или смещение;
- размер и выравнивание;
- класс хранения;
- параметры функции;
- видимость;
- место объявления;
- признаки использования;
- связь с внешним символом.

Основные операции:

```text
insert(name, information)
lookup(name)
begin_scope()
end_scope()
```



## 7.5. Таблица символов для блочной структуры

Для вложенных блоков:

```text
{
    int x;
    {
        double x;
        ...
    }
}
```

внутреннее объявление скрывает внешнее.

### Отдельная таблица для каждой области

Каждая область имеет свою хеш-таблицу и ссылку на внешнюю:

```text
scope_2 → scope_1 → global_scope
```

Поиск начинается в текущей области и продолжается наружу.

### Общая таблица со стеками объявлений

Для каждого имени хранится стек действующих объявлений. При входе в область добавляются новые записи, при выходе они удаляются.

Такой подход позволяет быстро восстанавливать скрытое объявление.



## 7.6. Хеш-функции

Хеш-таблица отображает имя в номер позиции:

\[
h:\Sigma^*\to\{0,\ldots,m-1\}.
\]

Хорошая функция должна:

- быстро вычисляться;
- равномерно распределять реальные идентификаторы;
- учитывать все значимые символы;
- минимизировать систематические коллизии.

Коллизии разрешаются:

- методом цепочек;
- открытой адресацией;
- двойным хешированием.

При цепочках среднее время поиска при ограниченном коэффициенте заполнения близко к

\[
O(1),
\]

но в худшем случае равно \(O(n)\).



## 7.7. LL(1)-анализ

LL означает:

- вход читается слева направо, Left-to-right;
- строится левый вывод, Leftmost derivation.

Число 1 означает один символ предпросмотра.

### Множество FIRST

\[
FIRST(\alpha)
\]

содержит терминалы, с которых может начинаться строка, выводимая из \(\alpha\). Если \(\alpha\Rightarrow^*\varepsilon\), в множество включается \(\varepsilon\).

### Множество FOLLOW

\[
FOLLOW(A)
\]

содержит терминалы, которые могут непосредственно следовать за \(A\) в выводимой строке.

Для начального символа:

\[
\$\in FOLLOW(S).
\]

### Построение таблицы

Для каждой продукции

\[
A\to\alpha
\]

выполняется:

1. для каждого

\[
a\in FIRST(\alpha)\setminus\{\varepsilon\}
\]

в ячейку \(M[A,a]\) помещается эта продукция;

2. если

\[
\varepsilon\in FIRST(\alpha),
\]

продукция помещается в \(M[A,b]\) для каждого

\[
b\in FOLLOW(A).
\]

Грамматика является LL(1), если ни в одной ячейке не возникает конфликта.

### Алгоритм анализа

В стеке находятся грамматические символы. В начале:

```text
$ S
```

На каждом шаге:

- если вершина стека — терминал и он равен текущему токену, терминал удаляется и вход продвигается;
- если вершина — нетерминал \(A\), выбирается продукция \(M[A,a]\);
- если ячейка пуста, фиксируется ошибка.

### Ограничения

Для LL(1) обычно требуется:

- устранить левую рекурсию;
- выполнить левую факторизацию;
- устранить конфликты FIRST/FIRST;
- устранить конфликты FIRST/FOLLOW.

Левая рекурсия:

\[
E\to E+T\mid T
\]

преобразуется:

\[
E\to TE',
\]

\[
E'\to +TE'\mid\varepsilon.
\]



## 7.8. LR(1)-анализ

LR означает:

- вход читается слева направо;
- строится правый вывод в обратном порядке.

LR-анализатор использует стек состояний и таблицы `ACTION` и `GOTO`.

### LR(1)-пункт

Пункт имеет вид

\[
[A\to\alpha\cdot\beta,\ a],
\]

где точка показывает уже распознанную часть, а \(a\) является символом предпросмотра.

### Операция closure

Если в множестве имеется

\[
[A\to\alpha\cdot B\beta,\ a],
\]

то добавляются пункты

\[
[B\to\cdot\gamma,\ b]
\]

для продукций \(B\to\gamma\) и

\[
b\in FIRST(\beta a).
\]

### Операция goto

\[
GOTO(I,X)
\]

получается сдвигом точки через символ \(X\) во всех подходящих пунктах с последующим вычислением замыкания.

### Действия анализатора

- **shift** — перенести токен в стек;
- **reduce** — свернуть правую часть продукции;
- **accept** — успешно завершить анализ;
- **error** — обнаружить синтаксическую ошибку.

### Конфликты

#### Shift/reduce

Неясно, переносить токен или выполнять свёртку.

#### Reduce/reduce

Неясно, по какой продукции выполнять свёртку.

Причины:

- неоднозначность грамматики;
- недостаточность выбранного класса анализатора;
- ошибки проектирования грамматики.

Канонический LR(1) имеет большое число состояний. LALR(1) объединяет состояния с одинаковыми LR(0)-ядрами, уменьшая таблицы, но иногда создавая дополнительные конфликты. GNU Bison по умолчанию ориентирован на LALR(1), а также поддерживает канонические LR(1), IELR и GLR-анализаторы. ([gnu.org](https://www.gnu.org/software/bison/?utm_source=openai))



## 7.9. Сравнение LL(1) и LR(1)

| Свойство | LL(1) | LR(1) |
||||
| Направление построения | сверху вниз | снизу вверх |
| Вывод | левый | правый в обратном порядке |
| Основная операция | выбор продукции | перенос и свёртка |
| Реализация вручную | сравнительно проста | существенно сложнее |
| Левая рекурсия | недопустима | допустима |
| Класс грамматик | уже | шире |
| Диагностика | часто понятнее | зависит от состояния и таблиц |
| Размер таблиц | обычно меньше | может быть большим |



## 7.10. Атрибутные грамматики

Атрибутная грамматика дополняет символы грамматики атрибутами и правилами их вычисления.

Пример:

\[
E\to E_1+T.
\]

Семантическое правило:

\[
E.value=E_1.value+T.value.
\]

### Синтезируемые атрибуты

Вычисляются из атрибутов дочерних узлов и передаются вверх.

Пример:

\[
E.type=combine(E_1.type,T.type).
\]

### Наследуемые атрибуты

Получаются от родителя или соседних символов.

Пример — передача ожидаемого типа выражению или таблицы текущей области объявлений.

### Граф зависимостей

Вершины соответствуют экземплярам атрибутов. Ребро

\[
a\to b
\]

означает, что атрибут \(b\) зависит от \(a\).

Вычисление атрибутов возможно в порядке топологической сортировки, если граф ацикличен.

### Частные классы

- S-атрибутные грамматики используют только синтезируемые атрибуты;
- L-атрибутные допускают ограниченные наследуемые атрибуты и удобны для нисходящего анализа.



## 7.11. Семантический анализ

После синтаксического разбора проверяются:

- наличие объявлений;
- уникальность объявлений;
- области действия;
- типы операндов;
- допустимость присваивания;
- число и типы аргументов;
- тип возвращаемого значения;
- доступность членов;
- допустимость `break`, `return`, `continue`;
- ограничения наследования;
- обязательность обработки исключений.

Результатом является аннотированное AST или первое промежуточное представление.



## 7.12. Построение AST семантическими действиями

Для продукции

\[
E\to E_1+T
\]

семантическое действие может быть записано как

\[
E.node=new\ Binary("+",E_1.node,T.node).
\]

Для

\[
F\to id
\]

получаем:

\[
F.node=new\ Identifier(id.entry).
\]

Так синтаксический анализатор одновременно проверяет структуру и формирует AST.

# 8. Автоматическое построение лексических и синтаксических анализаторов

## 8.1. Общий принцип

Генератор анализатора получает формальное описание языка и создаёт программу-распознаватель.

```text
описание лексики
        ↓
генератор сканера
        ↓
лексический анализатор

контекстно-свободная грамматика
        ↓
генератор парсера
        ↓
синтаксический анализатор
```

Это пример предметно-ориентированной трансляции: спецификация языка сама служит входом для другого транслятора.



## 8.2. Генерация лексического анализатора

Вход генератора состоит из правил:

```text
регулярное выражение → действие
```

Пример:

```text
[0-9]+        return INTEGER
[a-zA-Z_][a-zA-Z0-9_]* return IDENTIFIER
"+"           return PLUS
[ \t\n]+      skip
```

Типовая реализация:

1. каждое регулярное выражение преобразуется в НКА;
2. автоматы объединяются общим начальным состоянием;
3. НКА преобразуется в ДКА;
4. принимающим состояниям назначаются действия;
5. учитывается приоритет правил;
6. таблица переходов сжимается;
7. генерируется программа обхода автомата.

При распознавании сканер запоминает:

- последнее принимающее состояние;
- позицию входа в этот момент;
- правило с наивысшим приоритетом.

Если дальнейший переход невозможен, выбирается последнее успешное распознавание. Это реализует правило максимальной лексемы.



## 8.3. Lex и Flex

Lex — классический генератор сканеров. Flex — распространённая реализация сходной модели.

Структура спецификации:

```text
определения
%%
правила
%%
пользовательский код
```

Пример:

```lex
DIGIT   [0-9]

%%
{DIGIT}+   { return NUMBER; }
"+"        { return PLUS; }
[ \t\n]+   { /* пропуск */ }
%%
```

Flex генерирует исходный файл с функцией `yylex`, которая распознаёт регулярные шаблоны и выполняет соответствующие действия. ([ftp.gnu.org](https://ftp.gnu.org/old-gnu/Manuals/flex-2.5.4/html_node/flex_4.html?utm_source=openai))

Дополнительные средства:

- состояния сканера;
- макроопределения регулярных выражений;
- обработка конца файла;
- сохранение текста лексемы;
- получение длины;
- изменение входного потока;
- счётчики строк.

Состояния необходимы, например, для строк, комментариев и интерполяции, в которых одна последовательность символов имеет разный смысл в разных контекстах.



## 8.4. Генерация LL-анализатора

Для LL(1)-грамматики генератор:

1. считывает продукции;
2. проверяет корректность символов;
3. вычисляет nullable;
4. вычисляет FIRST;
5. вычисляет FOLLOW;
6. строит таблицу \(M[A,a]\);
7. обнаруживает конфликты;
8. генерирует табличный анализатор либо процедуры рекурсивного спуска.

Для продукции

\[
E\to TE'
\]

может быть создана функция:

```text
parse_E():
    parse_T()
    parse_E_prime()
```

Выбор альтернативы определяется символом предпросмотра.



## 8.5. Генерация LR-анализатора

LR-генератор:

1. расширяет грамматику продукцией

\[
S'\to S;
\]

2. строит начальное замыкание;
3. вычисляет множество LR-состояний;
4. строит переходы `goto`;
5. формирует таблицы `ACTION` и `GOTO`;
6. обнаруживает конфликты;
7. применяет приоритеты и ассоциативность;
8. генерирует стековый анализатор.

Исполняющий алгоритм:

```text
поместить начальное состояние в стек

цикл:
    s = вершина стека
    a = текущий токен
    действие = ACTION[s,a]

    shift t:
        поместить a и t
        прочитать следующий токен

    reduce A → β:
        удалить из стека элементы для β
        s = новая вершина
        поместить A и GOTO[s,A]

    accept:
        завершить успешно

    error:
        выполнить восстановление
```



## 8.6. Yacc и Bison

Yacc — классический генератор восходящих анализаторов. GNU Bison совместим с основной моделью Yacc.

Структура:

```text
объявления
%%
грамматические правила
%%
пользовательский код
```

Пример:

```bison
expr:
      expr '+' term   { $$ = make_add($1, $3); }
    | term            { $$ = $1; }
    ;
```

Здесь:

- `$1`, `$3` — атрибуты символов правой части;
- `$$` — атрибут левой части;
- действие строит узел AST.

Bison преобразует аннотированную КС-грамматику в исходный код синтаксического анализатора. Парсер запрашивает токены у лексического анализатора и выполняет семантические действия при свёртках. ([gnu.org](https://www.gnu.org/software/bison/manual/html_node/Bison-Parser.html?utm_source=openai))

Средства Bison включают:

- объявления токенов;
- семантические типы;
- приоритет и ассоциативность;
- координаты конструкций;
- обработку ошибок;
- LALR, IELR, LR и GLR-режимы.



## 8.7. ANTLR

ANTLR — генератор распознавателей и трансляторов структурированного текста.

Он позволяет по грамматике создавать:

- лексический анализатор;
- синтаксический анализатор;
- дерево разбора;
- обходчик дерева;
- listener;
- visitor.

ANTLR поддерживает объединённые и раздельные описания лексера и парсера. Из грамматики создаётся парсер, который может строить и обходить деревья разбора. ([antlr.org](https://www.antlr.org/?utm_source=openai))

Пример:

```antlr
grammar Expr;

expr
    : expr '*' expr
    | expr '+' expr
    | INT
    ;

INT : [0-9]+;
WS  : [ \t\r\n]+ -> skip;
```

Семантику удобно отделять от грамматики посредством visitor или listener, чтобы описание синтаксиса не зависело от языка реализации.



## 8.8. Другие инструменты

- **JavaCC** — генерация анализаторов для Java.
- **JFlex** — лексические анализаторы для Java.
- **CUP** — LALR-анализаторы для Java.
- **Coco/R** — генерация сканера и рекурсивного спуска.
- **Menhir** — LR-анализаторы для OCaml.
- **Happy** и **Alex** — парсер и сканер для Haskell.
- **re2c** — генерация быстрых лексических анализаторов.
- **PEG-генераторы** — анализаторы на основе parsing expression grammars.



## 8.9. Взаимодействие сканера и парсера

Сканер возвращает:

- код токена;
- семантическое значение;
- координаты.

```text
scanner:
    "123" → NUMBER, value=123, line=5, column=8
```

Парсер использует категорию для синтаксического решения, а атрибут — для построения AST.

```text
символы
   ↓ scanner
токены + значения
   ↓ parser
дерево разбора / AST
```



## 8.10. Обработка ошибок

Генератор может создавать механизмы:

- удаления ошибочного токена;
- вставки ожидаемого токена;
- пропуска входа до синхронизирующего символа;
- специального нетерминала ошибки;
- формирования множества ожидаемых токенов.

Синхронизирующими символами часто являются:

```text
;  }  end  else
```

Хорошее сообщение должно содержать:

- координату;
- найденный токен;
- ожидаемые категории;
- контекст;
- по возможности предполагаемое исправление.



## 8.11. Преимущества и недостатки генераторов

### Преимущества

- спецификация ближе к формальному описанию;
- меньше ручного кода;
- автоматическая проверка конфликтов;
- воспроизводимость;
- проще менять грамматику;
- разделение синтаксиса и реализации;
- возможность визуализации автоматов и деревьев.

### Недостатки

- сложность диагностики конфликтов;
- зависимость от конкретного инструмента;
- встроенные действия могут связывать грамматику с языком реализации;
- сгенерированный код сложнее читать;
- некоторые контекстные свойства требуют ручной обработки;
- сообщения об ошибках по умолчанию могут быть недостаточно понятными.

# 9. Оптимизация программ при компиляции

## 9.1. Понятие оптимизации

Оптимизация — семантически корректное преобразование программы, направленное на улучшение некоторого критерия:

- времени выполнения;
- размера кода;
- энергопотребления;
- числа обращений к памяти;
- использования регистров;
- степени параллелизма.

Преобразование должно сохранять наблюдаемое поведение в рамках семантики языка:

\[
P\equiv T(P).
\]

Оптимизация не обязана находить глобально оптимальную программу. В общем случае такая задача невозможна или вычислительно непрактична.

Компилятор применяет набор локальных преобразований и эвристик. Реальные системы используют проходы удаления мёртвого кода, распространения констант, глобальной нумерации значений, инлайнинга и оптимизации циклов. ([llvm.org](https://llvm.org/docs/Passes.html?utm_source=openai))



## 9.2. Классификация оптимизаций

### По области действия

- локальные — внутри базового блока;
- глобальные — в пределах процедуры;
- цикловые;
- межпроцедурные;
- общепрограммные.

### По зависимости от машины

- машинно-независимые;
- машинно-зависимые.

### По цели

- скорость;
- размер;
- энергопотребление;
- векторизация;
- уменьшение памяти;
- улучшение локальности.



## 9.3. Базовый блок

**Базовый блок** — максимальная последовательность команд с:

- одним входом в начало;
- одним выходом из конца;
- отсутствием переходов внутрь, кроме перехода к первой команде;
- отсутствием переходов наружу, кроме последней команды.

Лидерами являются:

1. первая команда процедуры;
2. цель любого перехода;
3. команда, следующая за условным или безусловным переходом.

Каждый лидер начинает новый базовый блок.



## 9.4. Оптимизация базового блока

Поскольку управление внутри блока линейно, анализ упрощается.

### Свёртка констант

```text
x = 3 * 4
```

заменяется:

```text
x = 12
```

### Распространение констант

```text
x = 10
y = x + 2
```

преобразуется:

```text
x = 10
y = 12
```

### Распространение копий

```text
x = y
z = x + 1
```

преобразуется:

```text
x = y
z = y + 1
```

Если присваивание `x = y` после этого не используется, оно удаляется.

### Алгебраические упрощения

\[
x+0\to x,
\]

\[
x\cdot1\to x,
\]

\[
x\cdot0\to0,
\]

если это допустимо семантикой типов и побочных эффектов.

Для чисел с плавающей точкой не все тождества действительных чисел допустимы из-за округления, бесконечностей и NaN.

### Устранение общих подвыражений

```text
t1 = a + b
...
t2 = a + b
```

Если \(a\) и \(b\) не изменились, второе вычисление заменяется использованием `t1`.

### Удаление мёртвого кода

```text
x = 10
x = 20
print(x)
```

Первое присваивание можно удалить.

Нельзя удалять операцию только потому, что её результат не используется, если операция имеет побочный эффект.

### Уменьшение стоимости операции

```text
x = y * 8
```

может заменяться сдвигом, если это выгодно на целевой машине и сохраняет семантику.



## 9.5. Локальная нумерация значений

Каждому вычисленному значению присваивается номер.

Для выражений ведётся таблица:

```text
(op, value_number(arg1), value_number(arg2))
    → value_number(result)
```

Если такая комбинация уже встречалась и операнды не изменились, новое вычисление избыточно.

Для коммутативных операций аргументы можно канонически упорядочить:

\[
a+b\equiv b+a.
\]

Нумерация значений является альтернативой построению DAG базового блока.



## 9.6. Граф потока управления

Граф потока управления:

\[
CFG=(V,E),
\]

где:

- \(V\) — базовые блоки;
- \(E\) — возможные передачи управления.

Добавляются:

- входная вершина;
- иногда выходная вершина.

Ребро \((B_i,B_j)\) существует, если после \(B_i\) управление может перейти в \(B_j\).

CFG используется для:

- достижимости;
- анализа циклов;
- потока данных;
- доминирования;
- размещения вычислений;
- удаления недостижимого кода.



## 9.7. Анализ потока данных

Каждому блоку сопоставляются множества `IN` и `OUT`. Общая форма:

\[
OUT[B]=F_B(IN[B]).
\]

В зависимости от задачи анализ бывает:

- прямой или обратный;
- may-анализ или must-анализ;
- объединяющий или пересекающий.

Для решения используется итерационный алгоритм:

1. инициализировать множества;
2. многократно пересчитывать блоки;
3. завершить при достижении неподвижной точки.

Поскольку множества конечны, а передаточные функции обычно монотонны, процесс завершается.



## 9.8. Достигающие определения

Определение переменной достигает точки, если существует путь от определения до точки без другого определения той же переменной.

Для прямого may-анализа:

\[
IN[B]
=
\bigcup_{P\in pred(B)}OUT[P],
\]

\[
OUT[B]
=
GEN[B]\cup(IN[B]\setminus KILL[B]).
\]

Применения:

- распространение констант;
- построение цепочек определение–использование;
- поиск возможных значений;
- удаление лишних присваиваний.



## 9.9. Активные переменные

Переменная активна в точке, если её текущее значение может быть использовано в будущем до следующего присваивания.

Это обратный анализ:

\[
OUT[B]
=
\bigcup_{S\in succ(B)}IN[S],
\]

\[
IN[B]
=
USE[B]\cup(OUT[B]\setminus DEF[B]).
\]

Применения:

- распределение регистров;
- удаление мёртвых присваиваний;
- определение времени жизни значений.



## 9.10. Доступные выражения

Выражение доступно на входе в блок, если на всех путях оно уже вычислялось и его операнды после этого не изменялись.

Это прямой must-анализ:

\[
IN[B]
=
\bigcap_{P\in pred(B)}OUT[P],
\]

\[
OUT[B]
=
GEN[B]\cup(IN[B]\setminus KILL[B]).
\]

Применение — устранение общих подвыражений и частичной избыточности.



## 9.11. Доминирование

Вершина \(d\) **доминирует** вершину \(n\), если любой путь от входа графа к \(n\) проходит через \(d\):

\[
d\operatorname{dom}n.
\]

Свойства:

1. каждая вершина доминирует сама себя;
2. вход доминирует все достижимые вершины;
3. отношение транзитивно;
4. для достижимых вершин отношение антисимметрично;
5. у каждой достижимой вершины, кроме входа, существует единственный непосредственный доминатор.

Множества доминаторов могут вычисляться уравнениями:

\[
Dom(entry)=\{entry\},
\]

\[
Dom(n)
=
\{n\}
\cup
\bigcap_{p\in pred(n)}Dom(p).
\]

### Непосредственный доминатор

\(idom(n)\) — ближайший строгий доминатор \(n\).

Рёбра

\[
idom(n)\to n
\]

образуют дерево доминаторов.

Если \(d\) является предком \(n\) в дереве доминаторов, то \(d\) доминирует \(n\).



## 9.12. Граница доминирования

Граница доминирования вершины \(x\):

\[
DF(x)=
\left\{
y\ \middle|\
\exists p\in pred(y):
x\operatorname{dom}p
\land
\neg(x\operatorname{sdom}y)
\right\}.
\]

То есть \(x\) доминирует хотя бы одного непосредственного предшественника \(y\), но не строго доминирует саму \(y\).

Интуитивно это места, в которых пути, контролируемые \(x\), встречаются с путями, не контролируемыми \(x\).

### Построение по дереву доминаторов

Локальная часть:

\[
DF_{local}(x)=
\{y\in succ(x)\mid idom(y)\ne x\}.
\]

Восходящая часть:

\[
DF_{up}(x)
=
\bigcup_{z\in children(x)}
\{y\in DF(z)\mid idom(y)\ne x\}.
\]

Итог:

\[
DF(x)=DF_{local}(x)\cup DF_{up}(x).
\]

Граница доминирования определяет места вставки \(\varphi\)-функций при построении SSA. LLVM и GCC непосредственно используют деревья доминаторов, границы доминирования и SSA-представление в оптимизирующих проходах. ([llvm.org](https://llvm.org/docs/Passes.html?utm_source=openai))



## 9.13. Сильно связанные компоненты

**Сильно связная компонента** ориентированного графа — максимальное множество вершин, в котором каждая вершина достижима из каждой другой.

Цикл содержится в нетривиальной сильно связной компоненте либо представлен петлёй вершины в себя.

Основные алгоритмы:

- алгоритм Косарайю;
- алгоритм Тарьяна;
- алгоритм Габова.

Сложность:

\[
O(V+E).
\]

### Алгоритм Тарьяна

Во время DFS каждой вершине назначаются:

- номер входа \(index[v]\);
- значение \(lowlink[v]\);
- признак нахождения в стеке.

Если

\[
lowlink[v]=index[v],
\]

вершина \(v\) является корнем очередной сильно связной компоненты. Вершины снимаются со стека до \(v\).

SCC используются для:

- анализа циклов;
- обработки рекурсивных процедур в графе вызовов;
- планирования оптимизаций;
- анализа зависимостей.



## 9.14. Естественные циклы

Ребро

\[
n\to h
\]

является обратным, если

\[
h\operatorname{dom}n.
\]

Вершина \(h\) является заголовком естественного цикла.

Естественный цикл содержит:

- \(h\);
- \(n\);
- вершины, из которых можно попасть в \(n\), не проходя через \(h\).

Цикл называется приводимым, если имеет единственный вход-заголовок. Неприводимые области имеют несколько входов и сложнее для анализа.

Сильно связная компонента и естественный цикл — не одно и то же: SCC описывает взаимную достижимость, а естественный цикл дополнительно связан с доминированием и единственным заголовком.



## 9.15. Канонизация и «чистка» циклов

Перед сложными преобразованиями цикл приводится к удобной форме.

Обычно формируются:

- **preheader** — блок перед входом;
- единый заголовок;
- единственное обратное ребро или latch;
- выделенные выходные блоки;
- каноническая переменная индукции;
- LCSSA-форма.

LLVM Loop Simplify, например, стремится обеспечить preheader, единственное обратное ребро и выделенные выходы, а LCSSA ограничивает внешние использования значений цикла специальными \(\varphi\)-узлами на выходах. ([llvm.org](https://llvm.org/docs/LoopTerminology.html?utm_source=openai))



## 9.16. Оптимизации циклов

### Вынесение инвариантов

```text
for i = 1 to n:
    x = a * b
    y[i] = x + i
```

Если `a` и `b` не изменяются:

```text
x = a * b

for i = 1 to n:
    y[i] = x + i
```

Операцию можно вынести, если:

- операнды инвариантны;
- вычисление безопасно выполнять раньше;
- не нарушаются зависимости и исключения;
- определение доминирует использования.

### Устранение лишних переменных индукции

```text
i = i + 1
j = j + 4
```

Если

\[
j=4i+c,
\]

одну переменную можно выразить через другую.

### Уменьшение стоимости

```text
address = base + i * 4
```

можно заменить последовательным увеличением адреса:

```text
address = address + 4
```

### Разворачивание

```text
for i = 0 to n-1:
    body(i)
```

преобразуется в обработку нескольких итераций за один проход.

Плюсы:

- меньше переходов;
- больше возможностей планирования;
- возможна векторизация.

Минусы:

- увеличение кода;
- необходимость обработки остатка;
- рост давления на регистры.

### Слияние циклов

Два цикла с одинаковыми границами объединяются для улучшения локальности.

### Разделение циклов

Один цикл разделяется на несколько, если это улучшает зависимости или локальность.

### Перестановка циклов

Меняется порядок вложенности для последовательного доступа к памяти.

### Векторизация

Независимые итерации выполняются SIMD-командами.

### Удаление цикла

Если результат не используется и цикл не имеет наблюдаемых побочных эффектов, он может быть удалён.



## 9.17. Граф зависимостей

Вершины графа зависимостей соответствуют операциям. Ребро показывает, что одна операция должна предшествовать другой.

### Истинная зависимость RAW

```text
x = ...
y = x + 1
```

Вторая операция использует результат первой.

### Антизависимость WAR

```text
y = x
x = ...
```

Первая должна прочитать старое значение до записи нового.

### Выходная зависимость WAW

```text
x = ...
x = ...
```

Необходимо сохранить порядок записей.

### Зависимость по управлению

Выполнение операции зависит от результата условия:

```text
if c:
    x = f()
```

### Зависимости памяти

```text
*p = 1
x = *q
```

Операции зависимы, если `p` и `q` могут указывать на одну область. Поэтому важны анализ псевдонимов и анализ указываемых объектов.

Граф зависимостей используется для:

- планирования команд;
- векторизации;
- распараллеливания;
- перестановки операций;
- оптимизации циклов.



## 9.18. SSA-представление

**Static Single Assignment** требует, чтобы каждое имя переменной имело ровно одно определение.

Исходная программа:

```text
x = 1
if c:
    x = 2
y = x + 1
```

SSA:

```text
x1 = 1

if c:
    x2 = 2

x3 = φ(x1, x2)
y1 = x3 + 1
```

Функция

\[
x_3=\varphi(x_1,x_2)
\]

выбирает значение в зависимости от входящего ребра CFG.

В цикле:

```text
i1 = φ(i0, i2)
...
i2 = i1 + 1
```

\(\varphi\)-функция объединяет начальное значение и значение с обратного ребра.

SSA явно связывает определения и использования и облегчает распространение констант, удаление мёртвого кода, нумерацию значений и анализ диапазонов. GCC описывает SSA как форму, в которой повторные присваивания получают новые версии, а в точках слияния вставляются PHI-узлы. ([gcc.gnu.org](https://gcc.gnu.org/onlinedocs/gccint/SSA.html?utm_source=openai))



## 9.19. Построение SSA

### Шаг 1. Найти места определений

Для каждой переменной \(v\) строится множество:

\[
DefSites(v).
\]

### Шаг 2. Вставить \(\varphi\)-функции

Начальный рабочий список содержит блоки из \(DefSites(v)\).

Для каждого блока \(x\) рассматриваются вершины из \(DF(x)\). Если в вершине \(y\) ещё нет \(\varphi\)-функции для \(v\), она вставляется.

Если \(y\) сама не была исходным местом определения, она добавляется в рабочий список. Таким способом вычисляется итерационная граница доминирования.

### Шаг 3. Переименовать переменные

Дерево доминаторов обходится в глубину. Для каждой исходной переменной хранится стек текущих версий.

При определении:

1. создаётся новая версия;
2. она помещается в стек;
3. левый операнд заменяется новой версией.

При использовании выбирается вершина стека.

При переходе к последователю заполняется соответствующий аргумент его \(\varphi\)-функции.

После выхода из блока созданные в нём версии удаляются из стеков.

### Минимальная и прореженная SSA

- минимальная SSA не вставляет заведомо лишние \(\varphi\)-функции с точки зрения графа определений;
- pruned SSA дополнительно использует анализ активности и не вставляет \(\varphi\)-функцию для переменной, неактивной на входе в блок.



## 9.20. Выход из SSA

Машинный код не имеет непосредственной команды \(\varphi\). Для каждого входящего ребра \(\varphi\)-функция заменяется присваиванием.

```text
x3 = φ(x1 from B1, x2 from B2)
```

превращается в:

```text
на ребре B1 → Join: x3 = x1
на ребре B2 → Join: x3 = x2
```

Проблемы:

1. копирования на одном ребре должны выполняться параллельно;
2. возможны циклы копирований;
3. критическое ребро может потребовать разбиения;
4. затем выполняется слияние совместимых имён и распределение регистров.

Цикл параллельных копий:

```text
a ← b
b ← a
```

последовательно реализуется с временной переменной:

```text
t = a
a = b
b = t
```



## 9.21. Глобальная оптимизация

Глобальная оптимизация работает во всей процедуре и использует CFG.

Примеры:

- глобальное распространение констант;
- глобальное удаление мёртвого кода;
- нумерация значений;
- устранение частичной избыточности;
- перемещение кода;
- упрощение переходов;
- объединение блоков;
- удаление недостижимых блоков;
- оптимизация циклов;
- распределение регистров.

Глобальная оптимизация должна учитывать все пути, а не только линейный порядок команд.



## 9.22. Межпроцедурная оптимизация

Межпроцедурный анализ рассматривает несколько процедур или всю программу.

Основная структура — граф вызовов:

\[
CG=(F,C),
\]

где \(F\) — процедуры, \(C\) — возможные вызовы.

### Встраивание

```text
y = square(x)
```

заменяется телом функции:

```text
y = x * x
```

Преимущества:

- устраняются расходы вызова;
- становятся видны константы;
- расширяются возможности оптимизации.

Недостатки:

- увеличивается код;
- возрастает время компиляции;
- увеличивается давление на кэш инструкций.

### Межпроцедурное распространение констант

Если во всех вызовах аргумент имеет одно значение, оно может быть подставлено в функцию.

### Удаление неиспользуемых параметров

Если параметр не влияет на поведение, он может быть удалён вместе с аргументами вызова.

### Удаление недостижимых функций

Функции, недостижимые из внешних точек входа, удаляются.

### Анализ эффектов

Для функции определяется:

- читает ли она глобальную память;
- изменяет ли память;
- создаёт ли исключения;
- возвращает ли новый объект;
- сохраняет ли переданные указатели.

### Анализ псевдонимов и указателей

Определяется, на какие объекты может ссылаться указатель. Это позволяет безопасно перемещать и удалять обращения к памяти.

### Девиртуализация

Если фактический тип объекта известен, виртуальный вызов заменяется прямым, после чего возможно встраивание.

### Анализ ускользания

Если объект не покидает пределы процедуры или потока, его можно:

- разместить не в общей куче;
- разложить на отдельные скалярные значения;
- исключить ненужную синхронизацию.

### Оптимизация времени компоновки

При LTO промежуточные представления нескольких модулей сохраняются до компоновки, что позволяет анализировать программу целиком. GCC отмечает, что совместная обработка нескольких файлов позволяет использовать информацию одного модуля при оптимизации другого. ([gcc.gnu.org](https://gcc.gnu.org/onlinedocs/gcc/Optimize-Options.html?utm_source=openai))
