\section{Примеры эффективных (полиномиальных) алгоритмов}

\begin{definition}
\textbf{Полиномиальный алгоритм} --- это алгоритм, время работы которого ограничено сверху многочленом от размера входных данных: $O(n^k)$, где $k$ --- константа, $n$ --- размер входа.
\end{definition}

К классу полиномиальных алгоритмов относятся быстрые алгоритмы поиска и сортировки, а также многие алгоритмы на графах (поиск пути, остовные деревья и др.). Задачи, решаемые такими алгоритмами, образуют класс $P$.

\subsection{Алгоритмы поиска и сортировки}

\textbf{1. Бинарный поиск (Binary Search).} $O(\log n)$.
\begin{itemize}
    \item \textit{Шаги:}
    \begin{enumerate}
        \item $L=0, R=n-1$.
        \item Пока $L \le R$, берем $M = \lfloor(L+R)/2\rfloor$.
        \item Если $A[M] == target$ --- нашли.
        \item Если $A[M] < target$, то $L = M+1$, иначе $R = M-1$.
    \end{enumerate}
    \item \textit{Пример:} Ищем 5 в $[1, 3, 5, 7]$. $M=1$ (значение 3). $3 < 5 \implies L=2$. $M=2$ (значение 5). Нашли!
\end{itemize}
\begin{proof}
(Корректность). Инвариант цикла: если искомый элемент присутствует в массиве, он всегда находится в границах $[L, R]$. Массив отсортирован. Если $A[M] < target$, то все элементы до $M$ тоже меньше $target$, следовательно, их можно безопасно исключить (сдвинув $L$). Размер отрезка уменьшается вдвое на каждом шаге, алгоритм конечен.
\end{proof}

\textbf{2. Сортировка слиянием (Merge Sort).} $O(n \log n)$.
\begin{itemize}
    \item \textit{Шаги:}
    \begin{enumerate}
        \item Если размер 1, массив отсортирован.
        \item Разделить массив пополам.
        \item Рекурсивно отсортировать обе части.
        \item Слить два отсортированных подмассива, используя два указателя.
    \end{enumerate}
    \item \textit{Пример:} $[4, 1, 3, 2] \to [4, 1]$ и $[3, 2] \to[1, 4]$ и $[2, 3]$. Слияние: берем мин(1, 2)=1, мин(4, 2)=2, мин(4, 3)=3, остается 4 $\to[1, 2, 3, 4]$.
\end{itemize}
\begin{proof}
(Корректность). Докажем по индукции. База: массив из 1 элемента отсортирован. Переход: по предположению индукции левая и правая половины отсортированы корректно. Процедура слияния на каждом шаге выбирает наименьший из текущих элементов обеих половин. Так как половины уже отсортированы, выбранный элемент является наименьшим среди всех оставшихся, что гарантирует корректность результата.
\end{proof}

\textbf{3. Быстрая сортировка (Quick Sort).} $O(n \log n)$ в среднем.
\begin{itemize}
    \item \textit{Шаги:}
    \begin{enumerate}
        \item Выбрать опорный элемент (pivot).
        \item Partition: перенести элементы $< pivot$ влево, $\ge pivot$ вправо.
        \item Рекурсивно отсортировать части.
    \end{enumerate}
    \item \textit{Пример:} $[3, 1, 4, 2, 5]$. Pivot = 3. Левая часть $\to[1, 2]$, правая $\to [4, 5]$. Итог: $[1, 2] \cup \{3\} \cup [4, 5] = [1, 2, 3, 4, 5]$.
\end{itemize}
\begin{proof}
(Корректность). После шага Partition опорный элемент стоит на своей финальной позиции, так как все элементы слева меньше него, а справа --- больше. По индукции, рекурсивная сортировка левой и правой частей приведет весь массив в полностью отсортированное состояние.
\end{proof}

\textbf{4. Сортировка пузырьком (Bubble Sort).} $O(n^2)$.
\begin{itemize}
    \item \textit{Шаги:}
    \begin{enumerate}
        \item Идти по массиву, меняя местами соседние элементы, если левый больше правого.
        \item Повторять, пока есть обмены.
    \end{enumerate}
    \item \textit{Пример:} $[3, 2, 1]$. Проход 1: $3>2 \to [2, 3, 1]$, $3>1 \to [2, 1, 3]$. Проход 2: $2>1 \to[1, 2, 3]$.
\end{itemize}
\begin{proof}
(Корректность). Инвариант: после $k$-й итерации внешнего цикла $k$ самых больших элементов массива гарантированно находятся на своих правильных местах в конце массива. Через $n$ итераций весь массив будет отсортирован.
\end{proof}

\textbf{5. Сортировка вставками (Insertion Sort).} $O(n^2)$.
\begin{itemize}
    \item \textit{Шаги:}
    \begin{enumerate}
        \item Считать первый элемент отсортированным.
        \item Взять следующий, сдвинуть бОльшие элементы левой (отсортированной) части вправо и вставить его.
    \end{enumerate}
    \item \textit{Пример:} $[4, 2, 3]$. Берем 2: сдвигаем 4 $\to[2, 4, 3]$. Берем 3: сдвигаем 4 $\to [2, 3, 4]$.
\end{itemize}
\begin{proof}
(Корректность). Инвариант: на $i$-м шаге префикс массива длины $i$ полностью отсортирован. Добавляя $i+1$-й элемент на правильную позицию, мы сохраняем префикс отсортированным.
\end{proof}

\textbf{6. Сортировка подсчётом (Counting Sort).} $O(n + k)$.
\begin{itemize}
    \item \textit{Шаги:}
    \begin{enumerate}
        \item Найти $k = \max(A)$.
        \item Посчитать частоты $C[x]$.
        \item Вычислить префиксные суммы в $C$ для стабильности.
        \item Разместить элементы в новый массив с конца.
    \end{enumerate}
    \item \textit{Пример:} $[2, 0, 2, 1]$. Частоты: $0\to 1, 1\to 1, 2\to 2$. Итог: один $0$, один $1$, два $2 \to[0, 1, 2, 2]$.
\end{itemize}
\begin{proof}
(Корректность). Если мы знаем, что строго меньше элемента $x$ в исходном массиве ровно $m$ элементов, то элемент $x$ должен занять позицию $m$ (в 0-индексации). Массив частот и префиксные суммы точно вычисляют эти индексы, что гарантирует правильное упорядочивание.
\end{proof}

\section{Алгоритмы на графах: Обходы и кратчайшие пути}

\subsection{Обходы графов}

\textbf{Поиск в ширину (BFS).} $O(V + E)$.
\begin{itemize}
    \item \textit{Шаги:}
    \begin{enumerate}
        \item Стартовую вершину пометить посещенной, добавить в очередь.
        \item Пока очередь не пуста, извлечь $u$.
        \item Всех непосещенных соседей $u$ отметить и добавить в очередь.
    \end{enumerate}
    \item \textit{Пример:} Граф: $1-2, 1-3, 2-4$. Старт 1. Очередь: $[1]$. Извлекаем 1, кладем 2, 3. Очередь: $[2, 3]$. Извлекаем 2, кладем 4. Порядок: 1, 2, 3, 4.
\end{itemize}
\begin{proof}
(Корректность кратчайших путей). Инвариант: очередь содержит вершины, отсортированные по расстоянию от старта (сначала все вершины на расстоянии $d$, затем на $d+1$). Следовательно, когда вершина впервые добавляется в очередь, для неё найден кратчайший путь.
\end{proof}

\textbf{Поиск в глубину (DFS).} $O(V + E)$.
\begin{itemize}
    \item \textit{Шаги:}
    \begin{enumerate}
        \item Пометить текущую вершину $u$ как посещенную.
        \item Для каждого соседа $v$ вершины $u$: если $v$ не посещена, рекурсивно запустить DFS($v$).
    \end{enumerate}
    \item \textit{Пример:} Граф: $A-B, A-C, B-D$. Старт $A$. Идем в $B$, оттуда в $D$. Из $D$ нет новых соседей, возвращаемся в $B$, затем в $A$. Идем в $C$. Порядок: $A, B, D, C$.
\end{itemize}
\begin{proof}
(Корректность обхода). DFS посетит все вершины, достижимые из стартовой. Предположим противное: существует достижимая непосещенная вершина. Тогда на каком-то кратчайшем пути к ней есть ребро $(x, y)$, где $x$ посещена, а $y$ нет. Но DFS не завершает обработку $x$, пока не проверит всех ее соседей, значит $y$ должна была быть посещена. Противоречие.
\end{proof}

\subsection{Кратчайшие пути: Алгоритм Дейкстры и переход к A*}

\textbf{Алгоритм Дейкстры.} $O(E \log V)$ (с мин-кучей).
Находит кратчайшие пути от стартовой вершины ко всем остальным во взвешенном графе без ребер отрицательного веса.

\begin{itemize}
    \item \textit{Шаги:}
    \begin{enumerate}
        \item Установить расстояние $d[s] = 0$, для остальных $d[v] = \infty$.
        \item Добавить все вершины в приоритетную очередь (кучу), упорядоченную по $d$.
        \item Пока очередь не пуста, извлечь вершину $u$ с минимальным $d[u]$.
        \item Для каждого соседа $v$ вершины $u$: провести релаксацию: если $d[u] + w(u, v) < d[v]$, обновить $d[v]$ и изменить ключ в куче.
    \end{enumerate}
    \item \textit{Пример:} Граф $S \xrightarrow{1} A \xrightarrow{2} T$ и $S \xrightarrow{4} T$. Старт $S$. $d[S]=0$. Извлекаем $S$. Релаксация: $d[A]=1$, $d[T]=4$. Из кучи извлекается $A$ (т.к. 1 < 4). Релаксация ребра $(A, T)$: $d[T] = \min(4, 1+2) = 3$. Извлекаем $T$. Кратчайшее расстояние до $T$ равно 3.
\end{itemize}
\begin{proof}
(Корректность). Докажем по индукции. Инвариант: при извлечении вершины $u$ из кучи, $d[u]$ равно истинному кратчайшему расстоянию $\delta(s, u)$. База: для $s$ это так ($0=0$). Переход: пусть это не так, и при извлечении $u$ существует путь короче. Тогда на истинном кратчайшем пути к $u$ есть первая вершина $y$, которая еще в куче, а ее предшественник $x$ уже извлечен. Поскольку веса неотрицательны, истинное расстояние до $u$ $\ge$ расстояния до $y$. Но $d[y]$ было корректно обновлено при извлечении $x$. Так как алгоритм сейчас выбрал $u$, а не $y$, то $d[u] \le d[y] \le \delta(s, u)$, что противоречит предположению о существовании более короткого пути.
\end{proof}

\textbf{Переход к алгоритму A*.}
Алгоритм Дейкстры распространяется как круги на воде, исследуя граф во всех направлениях равномерно. В прикладных задачах (например, маршрутизация на карте) мы часто знаем координаты цели и можем оценить направление к ней. Чтобы направить поиск в сторону цели и не исследовать заведомо плохие ветки, алгоритм Дейкстры обобщают, добавляя \textbf{эвристику}. Так получается алгоритм A*.

\textbf{Алгоритм A* (A-star).} Информированный поиск.
\begin{itemize}
    \item \textit{Функция оценки:} $f(v) = g(v) + h(v)$, где $g(v)$ --- стоимость пути от старта (как $d$ в Дейкстре), а $h(v)$ --- эвристика (оценка от $v$ до цели). Приоритетная очередь сортируется по $f(v)$.
    \item \textit{Шаги:} Аналогично Дейкстре, но в кучу элементы кладутся с ключом $f(v) = g(v) + h(v)$. Алгоритм завершается, как только извлекается \textit{целевая} вершина.
    \item \textit{Пример:} Граф $S-A-T$. Стоимости ребер 1. Цель $T$. Эвристика: $h(S)=2, h(A)=1, h(T)=0$. Для $S$: $f(S) = 0+2=2$. Извлекаем $S$. Сосед $A$: $g(A)=1, f(A)=1+1=2$. Извлекаем $A$. Сосед $T$: $g(T)=2, f(T)=2+0=2$. Извлекаем $T$.
\end{itemize}
\begin{proof}
(Корректность / Оптимальность). Эвристика $h(v)$ называется \textbf{допустимой} (admissible), если она никогда не переоценивает реальную стоимость $h^*(v)$. Если A* извлекает целевую вершину $T$, то найден путь $g(T)$. Предположим, существует оптимальный путь $C^* < g(T)$. Тогда на этом оптимальном пути есть непосещенная вершина $n$, находящаяся в очереди. Ее оценка $f(n) = g(n) + h(n) \le g(n) + h^*(n) = C^*$. Значит, $f(n) \le C^* < g(T) = f(T)$. Следовательно, $n$ была бы извлечена из очереди раньше, чем $T$. Противоречие. Значит, A* всегда находит кратчайший путь.
\end{proof}

\section{Остовные деревья и теоремы об их количестве}

\begin{definition}
\textbf{Остовное дерево} связного неориентированного графа --- это подграф, являющийся деревом и содержащий все вершины исходного графа.
\end{definition}

\textbf{Формула Кэли (Cayley's formula):} Количество различных остовных деревьев в полном графе $K_n$ на $n$ занумерованных вершинах равно $n^{n-2}$.
\begin{proof}
(Через коды Прюфера). Установим биекцию между множеством всех остовных деревьев на $n$ вершинах и множеством всех последовательностей длины $n-2$, состоящих из чисел от 1 до $n$.
Построение кода по дереву: найдем лист с наименьшим номером, запишем номер его единственного соседа в последовательность, удалим этот лист. Повторяем процесс, пока не останется 2 вершины. Так как шагов $n-2$, длина кода $n-2$.
Восстановление: степени вершин в дереве на 1 больше числа их вхождений в код. Находим минимальный номер вершины, отсутствующей в коде (ее степень 1 --- это лист). Соединяем её с первой вершиной в коде, удаляем элемент из кода и виртуально уменьшаем степень. Этот процесс детерминированно и однозначно восстанавливает дерево. Так как количество последовательностей длины $n-2$ из алфавита $n$ равно $n^{n-2}$, и это биекция, количество деревьев тоже $n^{n-2}$.
\end{proof}

\begin{theorem}
\textbf{Теорема Татта — Нэша-Уильямса:} Граф содержит $k$ попарно непересекающихся (по ребрам) остовных деревьев тогда и только тогда, когда для любого разбиения множества вершин $V$ на $r$ связных компонент $\mathcal{P}$, количество ребер графа, соединяющих вершины из разных компонент (обозначим $e(\mathcal{P})$), удовлетворяет:
$e(\mathcal{P}) \ge k(r-1)$.
\end{theorem}{Теорема Татта — Нэша-Уильямса:}
\begin{proof}
\textit{Необходимость.} Каждое остовное дерево при стягивании компонент разбиения $\mathcal{P}$ в точки должно оставаться связным, то есть должно содержать как минимум $r-1$ ребер, соединяющих эти $r$ компонент. Поскольку мы ищем $k$ непересекающихся по ребрам деревьев, суммарно они должны использовать как минимум $k(r-1)$ ребер разреза. Значит, $e(\mathcal{P}) \ge k(r-1)$.\\
\textit{Достаточность.} (Идея через матроиды). Зададим графовый матроид $M(G)$. Мы ищем $k$ независимых множеств ранга $V-1$. По теореме Эдмондса об объединении матроидов, объединение $k$ экземпляров матроида $M$ является матроидом с ранговой функцией $r_{union}(A) = \min_{X \subseteq A} (k \cdot r(X) + |A \setminus X|)$. Условие того, что в графе есть независимое множество ранга $k(|V|-1)$, алгебраически эквивалентно тому, что минимум функции для любого разбиения не меньше $k(|V|-1)$. Подстановка параметров в эту формулу в точности приводит к неравенству $e(\mathcal{P}) \ge k(r-1)$.
\end{proof}

\subsection{Минимальное остовное дерево (MST)}
\textbf{Алгоритм Прима} ($O(E \log V)$):
\begin{itemize}
    \item \textit{Шаги:}
    \begin{enumerate}
        \item Начать с любой вершины, добавить её в $T$.
        \item На каждом шаге выбирать ребро минимального веса, соединяющее $T$ с вершиной $v \notin T$, добавлять его и $v$ в $T$.
        \item Повторять до охвата всех вершин.
    \end{enumerate}
    \item \textit{Пример:} Граф-треугольник $A-B(1), B-C(2), A-C(3)$. Старт $A$. Доступны ребра веса 1 и 3. Берем $(A, B)$ веса 1. Теперь $T=\{A, B\}$. Доступны ребра $(A, C, 3)$ и $(B, C, 2)$. Выбираем 2. $T=\{A, B, C\}$. Вес MST = 3.
\end{itemize}
\begin{proof}
(Корректность, Лемма о безопасном ребре). Пусть $S$ --- множество вершин уже в остове. Разрез $(S, V \setminus S)$ разделяет граф. Чтобы дерево связывало все вершины, оно обязано пересекать этот разрез. Ребро минимального веса, пересекающее разрез, обязано входить в минимальный остов, иначе замена ребра, пересекающего этот разрез в альтернативном остове, на наше минимальное ребро строго уменьшила бы вес остова (что противоречит его минимальности).
\end{proof}

\section{Сети, Потоки и Разрезы}

\begin{definition}
\textbf{Граф-сеть} --- ориентированный граф с истоком $s$, стоком $t$ и пропускной способностью ребер $c(e) \ge 0$.
\end{definition}

\begin{definition}
\textbf{Поток} --- функция $f: E \to \mathbb{R}$, где $0 \le f(e) \le c(e)$, с сохранением потока во всех узлах, кроме $s$ и $t$.
\end{definition}

\begin{definition}
\textbf{Остаточная сеть $G_f$} --- граф, где для каждого ребра $(u,v)$ остаточная пропускная способность $c_f(u, v) = c(u, v) - f(u, v)$. Если $f(u, v) > 0$, то в $G_f$ добавляется обратное ребро $(v, u)$ с $c_f(v, u) = f(u, v)$. Путь из $s$ в $t$ в $G_f$ --- \textbf{дополняющий путь}.
\end{definition}

\begin{definition}
\textbf{Разрез $(S, T)$} --- разбиение $V$ на $S$ и $T$, где $s \in S, t \in T$. Пропускная способность разреза: $c(S, T) = \sum_{u \in S, v \in T} c(u, v)$.
\end{definition}

\begin{theorem}
\textbf{Теорема Форда-Фалкерсона (Min-cut Max-flow):} Величина максимального потока равна пропускной способности минимального разреза.
\end{theorem}
\begin{proof}
(Идея) Очевидно, что любой поток $|f|$ не превышает емкость любого разреза $c(S, T)$ (Слабая двойственность). Алгоритм Форда-Фалкерсона ищет дополняющие пути. Когда таких путей больше нет, множество достижимых из $s$ вершин в $G_f$ образует множество $S$, а остальные --- $T$. Для всех ребер из $S$ в $T$ $f(u, v) = c(u, v)$, а из $T$ в $S$ поток равен 0. Следовательно, $|f| = c(S, T)$, что доказывает как максимальность потока, так и минимальность данного разреза.
\end{proof}

\textbf{Алгоритм Форда-Фалкерсона.}
\begin{itemize}
    \item \textit{Шаги:}
    \begin{enumerate}
        \item Изначально поток $f=0$.
        \item Построить $G_f$.
        \item Найти любой путь из $s$ в $t$ в $G_f$ (с помощью BFS/DFS).
        \item Найти минимальную $c_f$ на этом пути ($\Delta$).
        \item Увеличить поток вдоль пути на $\Delta$.
        \item Повторять шаги 2-5, пока есть дополняющий путь.
    \end{enumerate}
\end{itemize}
\begin{proof}
(Корректность). Алгоритм останавливается, когда в $G_f$ нет пути $s \to t$. Пусть $S$ --- множество вершин, достижимых из $s$ в финальной $G_f$, $T = V \setminus S$. Ясно, что $s \in S, t \in T$. Для любого ребра из $S$ в $T$ в $G$ остаточная емкость $0$, значит $f(u, v) = c(u, v)$. Для ребра из $T$ в $S$ поток 0 (иначе было бы обратное ребро в $G_f$). Следовательно, суммарный поток из $s$ в $t$ в точности равен пропускной способности разреза $(S, T)$. Поскольку поток не может превышать емкость \textit{любого} разреза (слабая двойственность), этот поток максимален, а разрез минимален.
\end{proof}

\subsection{Глобальный минимальный разрез: Алгоритм Каргера}
\begin{itemize}
    \item \textit{Шаги:}
    \begin{enumerate}
        \item Выбрать случайное ребро.
        \item Стянуть его (объединить концы, удалить петли).
        \item Повторять, пока не останется 2 вершины. Количество ребер между ними --- размер разреза. Запускаем полиномиальное число раз и берем минимум.
    \end{enumerate}
    \item \textit{Пример:} Квадрат $A-B, B-C, C-D, D-A$. Стянем $A-B$ в $AB$. Ребра: $(AB, C), (C, D), (D, AB)$. Стянем $C-D$ в $CD$. Остались вершины $AB$ и $CD$, между ними 2 ребра. Размер разреза = 2.
\end{itemize}
\begin{proof}
(Корректность). Пусть $C$ --- некоторый минимальный разрез размера $k$. На каждом шаге в графе $\ge k$ ребер у каждой вершины, значит всего ребер $\ge kV/2$. Вероятность стянуть ребро из $C$ на первом шаге: $\le k / (kV/2) = 2/V$. Вероятность того, что разрез $C$ "выживет" (не стянется) за $V-2$ шага:
$\prod_{i=0}^{V-3} \left(1 - \frac{2}{V-i}\right) = \frac{V-2}{V} \cdot \frac{V-3}{V-1} \cdot \dots \cdot \frac{2}{4} \cdot \frac{1}{3} = \frac{2}{V(V-1)}$.
Вероятность не равна нулю (ограничена полиномом снизу). Выполнив алгоритм $O(V^2 \log V)$ раз, вероятность ошибки стремится к 0.
\end{proof}

\subsection{Поток минимальной стоимости (Successive Shortest Path)}
Каждому ребру, помимо пропускной способности $c(e)$, задана стоимость $a(e)$. Задача: найти поток заданной величины (или максимальный), суммарная стоимость которого $\sum f(e)a(e)$ минимальна.
\begin{itemize}
    \item \textit{Шаги:}
    \begin{enumerate}
        \item $f=0$.
        \item Построить $G_f$, где стоимости обратных ребер равны $-cost(e)$.
        \item  Найти путь из $s$ в $t$ \textbf{минимальной стоимости} (используя Форда-Беллмана или Дейкстру с потенциалами Джонсона).
        \item Пустить максимально возможный поток вдоль этого пути. Повторять, пока не наберем нужный поток $F$.
    \end{enumerate}
\end{itemize}
\begin{proof}
(Корректность). Теорема: поток имеет минимальную стоимость тогда и только тогда, когда в остаточной сети $G_f$ нет ориентированных циклов отрицательной стоимости. Добавляя поток вдоль \textit{кратчайшего пути}, мы не создаем отрицательных циклов (доказывается через потенциалы вершин). Индукцией по шагам показывается, что на каждом этапе мы имеем оптимальный поток текущей величины.
\end{proof}

\section{Двудольные графы и Паросочетания}

\begin{definition}
\textbf{Паросочетание} --- множество попарно не смежных ребер графа.
\begin{itemize}
    \item \textbf{Максимальное} --- паросочетание с наибольшим числом ребер.
    \item \textbf{Минимальное} --- обычно понимают как минимальное по весу совершенное паросочетание (задача о назначениях) или минимальное максимальное паросочетание (наименьшее по размеру, к которому нельзя добавить ребро).
    \item \textbf{Совершенное} --- паросочетание, покрывающее все вершины графа.
\end{itemize}
\textbf{Вершинное покрытие} --- множество вершин, инцидентное каждому ребру графа. (По теореме Кёнига в двудольных графах размер макс. паросочетания равен размеру мин. вершинного покрытия).
\end{definition}

\textbf{Теорема Холла:} В двудольном графе с долями $L$ и $R$ существует паросочетание, покрывающее $L$, $\iff$ $\forall S \subseteq L: |N(S)| \ge |S|$.
\begin{proof}
\textit{Необходимость.} Если есть паросочетание, покрывающее $L$, то каждая вершина из $S$ имеет уникального соседа в $N(S)$, значит соседей не меньше, чем элементов в $S$.\\
\textit{Достаточность.} Докажем через макс. поток. Добавим исток $s$, соединим с вершинами $L$ (емкость 1). Добавим сток $t$, соединим $R$ с $t$ (емкость 1). Ребра между $L$ и $R$ имеют емкость $\infty$. Если паросочетания, покрывающего $L$, нет, то макс. поток $< |L|$. По т. Форда-Фалкерсона есть минимальный разрез $(S', T')$ емкости $< |L|$. Пусть $A = L \cap S'$, $B = R \cap S'$. Емкость разреза складывается из $c(s, L \setminus A) + c(A, R \setminus B) + c(B, t)$. Так как емкость конечна, $c(A, R \setminus B) = 0$, то есть соседи $A$ лежат только в $B$ ($N(A) \subseteq B$). Емкость разреза: $|L| - |A| + |B| < |L| \implies |B| < |A|$. Значит, $|N(A)| \le |B| < |A|$, что нарушает условие Холла.
\end{proof}

\subsection{Венгерский алгоритм}
Решает задачу о назначениях (поиск совершенного паросочетания минимального веса в полном двудольном графе $n \times n$) за $O(n^3)$.
\begin{itemize}
    \item \textit{Шаги:}
    \begin{enumerate}
        \item Вычесть минимум строки из каждого элемента строки.
        \item Вычесть минимум столбца из каждого элемента столбца.
        \item Найти максимальное паросочетание, состоящее только из нулевых элементов. Если размер $n$ --- конец.
        \item Иначе провести минимальное количество линий через строки и столбцы, покрывающие все нули.
        \item Найти минимум среди непокрытых элементов ($\Delta$). Вычесть $\Delta$ из непокрытых и прибавить $\Delta$ к элементам на пересечении линий. Вернуться к шагу 3.
    \end{enumerate}
\end{itemize}
\begin{proof}
(Корректность). Если к любой строке или столбцу матрицы стоимостей прибавить/вычесть константу, оптимальное назначение не изменится (так как любое совершенное паросочетание берет ровно по одному элементу из каждой строки и столбца, общая стоимость изменится ровно на эту константу). Алгоритм поддерживает инвариант $C \ge 0$. Если мы находим совершенное паросочетание стоимости 0 в измененной матрице, оно гарантированно является минимальным (ниже 0 быть не может), а значит, оптимальным и для исходной матрицы.
\end{proof}
